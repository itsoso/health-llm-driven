## 问题与范围

用户要求继续其他部分的优化，并分析输入 token 普遍偏大的架构原因。本轮刷新远端后为 `f201d85b4`，与工作区起点的运行代码一致。既有审计和上一轮实现作为起点，不重复将公共天气结果外推为健康任务收益。

[架构分析](../reviews/2026-10-04-prompt-architecture.md) 沿真实 Pi/provider/orchestrator 链路确认：执行和回答规则混在一起、工具内部说明仍宽、历史按条数限额、内外层可能重复合成。准入沿用既有性能与可靠性修复，不新增健康对象、写权限、数据库语义或外发对象。

本轮实现：

1. 增加服务端选择的 `synthesis_only` 提示词阶段。仅已有 composed/diet 无工具回答入口使用；保留 R4、临床来源、分诊和基因约束，移除写入/删除/提醒/创作和工具选择的执行手册。失败/未知也可能需要终态回答，明确不将其冒充已核验事实。
2. 在实际流式、非流式和直连网关 provider 边界压缩工具 JSON。只移除合法 JSON 字符串外空白；原 Pi 记录、数字词法、重复键、字段顺序和字符串保持，非法与多模态内容原样传递。不新增重试或模型调用。
3. 日志增加工具结果、普通对话、工具调用参数的独立长度及 `read_synthesis` 标签；旧预算指标保留。近似输入仍是字符估计，真实 token 另取 provider API 用量。

三项复用 `DOMAIN_PROMPT_OPTIMIZATION`，关闭即可退回原提示词与传输。日志计数不包含正文。本轮没有调整生产配置、模型档位、同意、临床规则、历史内容或写入协议。

## 验收与实际结果

验收目标：固定只读回答系统提示词至少减少 30%；输入证据不变；不破坏普通工具链、混合任务、失败语义、单位、精度、用户隔离及未知说明。发生上述退化即停止发布并回退。

真实 API 回放使用同一 `qwen3.8-max`、temperature=0。输入来自真实 Pi 的固定合成请求帧；两侧把测试中的分诊占位符替换为相同的真实分诊文本。只重放最终回答帧，未让真实回复反向驱动整条 Agent 链路。
