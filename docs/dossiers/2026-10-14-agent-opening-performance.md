## 基线与目标

以用户提供餐食截图对应 owner 的最近聊天附件、同一最近会话列表作只读探测。生产 PostgreSQL 会话强制 READ ONLY；不输出或落盘图片、签名 URL、用户身份、会话标题或正文。图片为开发电脑到生产 HTTPS；列表为生产路由直接调用及 SQL 分段，不包含客户端网络。每种参数五次交替配对，nearest-rank P50/P95/P99 仅为诊断样本。

| 请求 | 旧参数 | 候选参数 |
|---|---|---|
| 聊天缩略图 | 原图 526749 bytes | preview 139824 bytes |
| 图片总耗时 P50/P95/P99，ms | 646.79 / 850.9 / 850.9 | 240.14 / 326.82 / 326.82 |
| 最近会话 | limit=20，4318 bytes | limit=1，240 bytes |
| 列表路由 P50/P95/P99，ms | 27.94 / 1083.26 / 1083.26 | 27.49 / 36.56 / 36.56 |
| 列表 SQL | 3 条；暖态约 23 ms | 3 条；暖态约 23 ms |

列表首个旧参数样本含进程与 ORM 冷启动，不能把该长尾差异归因于 limit；这里只主张传输/解析负担下降。两种列表参数返回的首条会话相同。

目标：同图片预览小于 200 KiB，配对总耗时 P50/P95 不劣于原图；恢复列表小于 1 KiB且选择相同首条。保持分页历史默认 20 条、未完成 turn 恢复顺序、用户隔离、签名与鉴权；不添加跨请求数据缓存。图片只复用既有 960px 私密预览端点及其容量/TTL，不新增后端成本类型。质量、错误率或时延退化则停止发布并修正，不建备份或回退副本。

## 实现

- `ChatMessageImage` 仅为当前 API 同 origin 的 chat/diet 路径添加 `variant=preview`，保留签名参数和鉴权 header；不改写本地、外部及医疗图片。
- 缩略图预览失败只回退一次原图，换图重新尝试预览；点击、保存和分享继续使用原图。没有自定义缓存 key 或扩展签名有效期。
- 恢复默认最近会话显式 limit=1，其他会话列表保持默认分页大小；不改恢复竞态、写回执或流式状态。
