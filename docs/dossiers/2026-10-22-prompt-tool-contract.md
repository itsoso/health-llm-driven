## 已核实问题与最小修复

- 食物照片示例使用 `health_record(type=...)`，真实 schema 必填 `record_type`；
  复杂分析示例使用 `health_analysis(type=...)`，真实 schema 必填 `analysis_type`，
  执行器只读取后者。修为 canonical 字段，并将全部相关示例与 schema 对照验证。
- 记录完成曾被描述为必须发起 health_record 调用；已有照片自动保存回执的路径
  不需要再调用。改为本轮对应操作的核验结果与回执，有回执不重复写，无回执不报成功。
- 照片一律记录、补剂直接执行的泛化指令与分析、待确认、缺事实路径冲突。
  改为遵守现有状态：分析不写，草稿等确认，剩余照片修正原餐，缺事实不猜。
- 查询及分析描述中的“不确定也选 comprehensive”可能诱导范围扩大；改为目标不明先澄清，
  comprehensive 只在用户请求与当前权限允许时使用。权限解析和执行代码不变。
