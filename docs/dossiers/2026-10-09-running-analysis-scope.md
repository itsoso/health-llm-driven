# 综合跑步分析请求的查询范围修复

状态：本地实现，待独立安全复审；未推送、未部署，未执行 OTA。

## 复现与原因

用户将身体背景、近期饮食睡眠、当前城市天气、跑步建议及 HTML 输出组合为一个请求。
旧纵向查询解析器将非历史查询子句视为未解析限制，返回 `longitudinal_read_scope_unresolved`。
仅修正日期解析仍不够：多域查询工具过滤会隐藏 `environment_check`，健康记录完成后
纯健康总结又会替换原始上下文并禁用后续工具。

## 修复边界

- 完整消费当前有效的复合请求语法，分别识别个人背景、近期饮食/睡眠、天气和答案要求。
  原始消息仍保留给模型和持久化层；不是删去任意不认识的词句。
- 饮食/睡眠范围仍由认证用户、服务端时间和既有日期解析器绑定；未指定天数的“最近”
  使用既有近 7 天范围并披露。身体背景不额外授权病史、运动、基因或补剂查询。
- 天气作为独立只读目标进入同一工具曝光/执行授权边界；城市限公共天气既有语法，
  参数绑定请求城市和当前天气，不能由模型扩大为另一城市、预报或额外用户参数。
- 此复合任务不提前切换到纯健康、无工具总结，保留天气工具、原始问题与工具结果。
  既有健康证据、失败结果及医疗安全检查不变；不授权健康写入。
- 不识别的地区/子句继续失败关闭；不是通用自然语言规划器或任意城市地理解析器。

  覆盖本人/其他用户/未来日期隔离、天气成功及失败、HTML 表达的原消息保留。
  模型和天气网络返回受控；不冒充真实模型、真实天气或线上验收。
