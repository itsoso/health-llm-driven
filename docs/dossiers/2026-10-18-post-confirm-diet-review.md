## 准入与根因

- 用户截图请求「帮我复盘这一天的饮食，给出下一餐的调整建议。」被错误拒绝为非本人查询。
- Router 为 quick_fix + safety；局部 System Map 未索引，已核查 Mobile 入口、执行器、只读授权和邻近测试，完整地图校验通过。
- 既有 post_confirm 入口传入记录 ID 和客户端日期，但其代词请求没有绑定到服务器的单日读取计划。模型只能自行提出查询，权限层无法证明主体和日期而拒绝。
- 恢复既有复盘功能，不新增产品对象、API schema 或数据库字段。

## 实现

- 仅完整匹配现有快捷请求且无附件时，根据认证用户和严格整数记录 ID 查询已持久化的本人饮食；数据库日期转为明确单日请求，进入既有计划、网关和读取路径。
- 原始用户消息仍原样持久化；客户端日期、食物、总量、主体和控制指令不参与授权，数据库校验上下文由服务器重建。
- 记录缺失、非本人、缺少上下文或 selector 格式错误均返回统一的重新选择/说明日期提示，不调用模型，不读取猜测日期。
- 用户改写快捷请求时丢弃旧入口上下文，完整新文本重新编译，不抹除取消、第三方、额外范围或写入要求。既有 replay/不确定写入恢复优先级保留。
