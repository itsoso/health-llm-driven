## 根因与修复边界

1. 外层 Web Cookie 已完成认证，但 Agent 内部工具调用只提取 Bearer；正确传递已认证凭据，保留主体、家庭代理和 API key 权限边界，不把凭据放入模型或日志。
2. 原子补剂适配器将明确认证拒绝归为未知写入。仅将可信第一方 401/403 和带写前标记的名称冲突视为明确拒绝；超时、未知 409、500、缺失或畸形回执继续视为不确定，禁止自动重试。
3. 相似补剂名不可自动映射成已有产品。名称冲突返回当前用户范围内的候选，整组零写入，并提示使用核对后的完整名称。
4. 多项缺单位后的“一粒”不能默认扩展到每项。仅在同用户、同会话、紧邻的服务端单位追问且 30 分钟内提供零模型调用的补充说明；不把历史变成写授权。此修复不是自动多轮续写，仍需用户在完整记录中明确各项名称、数量和单位。
5. 原子批量接口仅由内部 Agent 消费。写前 409 的 `detail` 由字符串变为 `{error_code, dispatch_started:false, message, candidates}`；成功回执不变。候选限当前用户最多三项，API 与适配器同批验证。没有直接调用该端点的 Web/Mobile UI，也没有 OpenAPI schema 变化。
