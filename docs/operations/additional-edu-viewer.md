# Additional Edu read-only viewer

A second explicitly identified parent needs read-only access to the existing Edu workspace. Preserve the original owner and all existing viewers. Account identities remain in private operational evidence, never this repository.

The existing runtime already accepts multiple viewer subjects. The initial one-shot activation operator did not support extending an installed list. `--existing-viewer-ids` now binds the exact previous list and appends one distinct viewer, with a separate per-viewer journal and the existing release lease. Initial activation retains its original journal and contract. Missing, conflicting, duplicate, owner-overlapping, or repeated viewer IDs fail closed. Resume checks the same old/new policy and journal binding.

No production authorization changed yet. Production application requires the exact reviewed installed revision, current-main CI, protected activation preflight and final process readback. Real login remains a separate acceptance step.

Health data sharing is separate: registered users must accept the family invitation with their own authenticated session. Edu activation does not grant Health data access or manufacture family consent.
