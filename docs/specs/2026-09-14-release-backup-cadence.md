# Technical Spec: 发布备份分层策略

> Status: approved
> Owner: Codex
> Updated: 2026-09-15

## Decision

用户明确要求发布跳过备份与站外归档，因此发布默认不执行数据库备份、恢复演练或站外上传。
仅 `DEPLOY_DATABASE_BACKUP=1` 显式启用以下分层策略；`0` 为跳过，其他值必须失败。
发布工具完整性、回滚 schema、运行态事务和上线健康验证仍执行，既有夜间任务不变。

显式启用时，保留发布的本地 PostgreSQL 压缩备份和完整恢复演练；把耗时的站外加密上传改为每日
一次，并让普通发布复用 24 小时内的已验证凭证。包含 managed migration 或无法可靠判断
迁移范围的发布，必须在数据库变更前同步完成站外上传与远端校验。

## Contract

- 显式启用备份的发布：新建本地备份、校验 FORCE RLS 数据段、恢复到临时库并验证结构。
- 每日夜间：age 本地加密、immutable 上传、远端 SHA-256 回读、HMAC 清单验证。
- 普通发布：要求最近成功凭证不超过 86,400 秒，且远端对象、`.sha256`、`.manifest`
  三件套仍同时存在；满足后只跳过本次站外上传。
- 迁移发布、生产基线不可判定、凭证缺失/过期/不安全或远端不完整：同步站外上传。
- 任何必需步骤失败：发布阻断；不得静默降级为无备份发布。

## Security

成功凭证只在远端哈希与 HMAC 验证完成后原子写入工作树外目录；目录 `0700`、文件 `0600`，
验证 owner、普通文件、非符号链接和单硬链接。凭证只含版本、验证时间和安全对象名，不含
数据库连接、密钥、手机号或健康数据。

## Rollback

设置 `DEPLOY_DATABASE_BACKUP=1` 可恢复发布备份；启用后的备份失败不得降级为跳过。
