状态:**已交付并归档(2026-06-18)**。架构定调:**health 系统为集大成的聚合器 —— 所有外部日历单向汇入,不外推**。

③ 聚合日历视图(mobile `/calendar`:各源事件 + 健康日程统一时间轴 + 多源管理 UI,只读)。
已取消(产品决定):**写回外部日历**(不外推)+ **系统内原生事件创建**(已有丰富健康事件 + 聚合视图足够)。
Kim 已实拉验证(83 事件)。

## Decision

把原来的「单 CalDAV 源 + 仅当日忙碌块」扩展为**多源、跨日期窗口、全量明细**的日历层,
并为任何 agent/LLM 读日历建立**唯一隐私出口**。

- **连接方式**:用户(及家人,如 Kim)的日历通过 **CalDAV**(可读凭据)或 **.ics 订阅链接**(只读)接入。每用户可挂多个源(`CalendarSource`),各自打标签/颜色/启停。
- **详细读写**:事件以全量明细(标题/地点/描述/参会人/状态/起止)同步进 `CalendarEvent`。用户自己的客户端经 `GET /calendar/events` 读到解密明细。
- **隐私脱敏(不可妥协)**:日历 → LLM/agent 的唯一门是 `caldav_sync.calendar_event_for_llm(event)`,只返回粗粒度 busy 窗口,**绝不**含 title/location/description/attendees/uid。这是 HARD boundary。
- **静态加密(防御纵深)**:凭据与事件 PII 在应用层 Fernet 加密后才入库(复用 device/garmin 同一把密钥)。隐私边界是 LLM 出口;静态加密是额外一层。

## Non-Goals (C1)

- 不写回外部日历(所有源 `writable=False`;CalDAV 双向同步是 C2)。
- 不做系统内原生日历(C3)。
- 不把日历明细喂给 specialist/orchestrator —— 它们只能拿 busy 窗口。
- 不为 agent 自动建/改事件。

## ASCII 数据流

```
外部源 (CalDAV / .ics)
   │  _fetch_source_events  (SSRF 护栏 _assert_safe_url → caldav.search / urllib+icalendar)
   ▼
sync_source / sync_all_sources  (每源 fail-soft;窗口全量替换 + (source_id,uid) 幂等)
   │
   ▼
CalendarEvent  (PII 加密存:title/location/description/attendees)
   │
   ├──► today_busy_blocks(db,user)  ──► day_schedule_service overrides["busy"]  ──► timing-solver
   │        (只出 [(HH:MM,HH:MM)],标题永不出函数;shape 与 v1 一致,消费方零改动)
   │
   ├──► GET /calendar/events (owner 自己的客户端) ──► 解密明细 (title/location/…)
   │
   └──► calendar_event_for_llm(event)  【隐私接缝 · HARD boundary】
            └──► {start,end,busy,all_day,source_label}  ──► 任何 agent/LLM 路径
                 (绝无 title/location/description/attendees/uid)
```

## C1 契约

| 能力 | 实现 |
|---|---|
| 多源(caldav + ics) | `CalendarSource`;`POST/GET/PUT/DELETE /calendar/sources` |
| 日期窗口全量明细读 | `sync_source(window_days_back=7, window_days_fwd=30)` + `GET /calendar/events?from=&to=` |
| 忙碌块派生 | `today_busy_blocks` 改为从 `CalendarEvent` 派生(跨所有源,排全天/零长) |
| 同步入口 | `POST /calendar/sync` → `sync_all_sources`(每源 try/except 隔离) |
| 隐私接缝 | `caldav_sync.calendar_event_for_llm` |
| SSRF | `_assert_safe_url`(caldav + ics 共用;旧名 `_assert_safe_caldav_url` 保留为别名) |

向后兼容:`CalendarCredential` / `CalendarBusyBlock` / `save_credentials` / `sync_today` / `_fetch_events` 保留;迁移把老凭据搬进一条 `CalendarSource`。

## 隐私接缝 = 不可妥协边界

任何未来读日历的 agent/specialist/orchestrator/skill,**必须**经 `calendar_event_for_llm`;
绝不直接读 `CalendarEvent.get_title()` 等明文进 prompt。守门测试在 `tests/test_calendar_v2.py::test_privacy_seam_strips_pii`(断言返回 dict 无 title/location/description/attendees/uid)。
