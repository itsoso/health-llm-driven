# 用药通知草稿的单时段只读核对

> Status: implemented locally; release pending
> Updated: 2026-10-20

## 决策与问题

客户端既有通知入口生成带日期、时刻和时区的只读草稿；用户发送后，后端缺少对应授权绑定，拒绝了本人查询。补齐整句解析、服务端范围绑定、实际查询和结果证据核验。

## 需求准入

- 分类：已有行为修复；面向当前用户的用药提醒核对。
- 核心环：Agenda → 用户核对 → ExecutionEvent 读取，不创建执行事实。
- 真源：认证账户、当前保存的 Medication 计划、MedicationLog；通知和模型不能提供 owner。
- 授权：用户发送固定草稿才允许读取指定日期/时区/时刻；打开通知仍只填草稿。
- 风险：用药/隐私，要求 safety-gate；处方未核验，不做临床判断或剂量调整。
- 成功：本人匹配时段计划和日志可查，未匹配/空记录如实说明；跨用户、跨日期/时段及写入均拒绝。
- 用户负担：沿用既有发送动作，不新增表单。

## 范围与边界

完整语句必须包含合法绝对日期、HH:mm 和与服务端当前时区相同的时区。北京时间对应 Asia/Shanghai。缺失、被引用、被否定、附加未知指令或改成第三方时，不降级到整日/全账户读取。保持普通设置提醒请求的既有路径。

查询通过现有 health_query/health_query_batch，模型只能提议 medication 维度及相同日窗口；时刻从原请求冻结，不能由模型字段改变。执行前重新核验原快照、当前账户、当前文本和工具参数。

返回限定时段的当前有效计划及该日期/时刻日志，两者分别展示。日志同时校验 MedicationLog 与 Medication 的 owner；只读取、不创建/更新/删除用药或服药记录。计划不证明历史通知内容，缺少日志不代表未服用。结果超界/异常要失败，不能返回假空结果。

完成判断要求实际返回同一天、同一时段的证据；整日结果不能冒充单时段结果。该范围不持久化为通用的整日“继续查询”授权。

## 验证与发布

覆盖固定客户端语句、单条/批量真实工具分发、保存回复、账户/日期/时区/时段隔离、禁止写入、损坏外键、空数据、超量和畸形计划。SQLite 快速回归与 PostgreSQL 验证分开记录；合成 provider 不冒充真实模型质量或线上验收。

不改 API、schema、客户端运行逻辑，只有客户端契约测试；本修复无需 OTA。完整 CI、独立审查和原发布收尾门禁仍适用。
