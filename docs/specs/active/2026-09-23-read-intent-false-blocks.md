# 明确读取和既有饮食修正的语义修复

Status: implementing · Owner: Codex · Updated: 2026-09-23

## 决策与准入

classification: bugfix。承接 PRD R3/R5/R9/R10，恢复明确本人查询及用户确认的
饮食修正；source_of_truth 为认证用户的已有记录和服务端绑定的上下文。
对象：WriteIntent、HealthTwin、ExecutionEvent；surface：Backend → Mobile Chat。
安全边界为健康写入、隐私和医疗证据；不作处方、诊断或因果判断，写入仍需
明确用户指令和既有确认/目标校验。不新增用户输入负担、数据表或后台同步。

## 最小流程与契约

1. 分析请求中的“给出你的建议”属于回答目标，不是查询条件。最近一周应绑定
   到用户时区的明确日期；未消费完的限制、其他人的记录不能被丢弃。
2. “睡眠血氧”必须携带实际血氧来源、窗口、质量和缺失边界，不得用仅睡眠
   时长/评分的结果冒充。本次仅读取本人范围内的血氧日汇总，复用既有来源
   排除规则；日汇总不能证明夜间覆盖、ODI 或诊断。不调用会回退到最近一夜的
   读取器。无法安全绑定时明确说明尚未查询，不归咎于用户未写明日期。
3. 基于已识别餐食修改今天午餐，识别为修改目标。仅通过既有服务端授权的
   前置查找定位本人、日期、餐别；没有唯一记录或没有可信餐食来源时澄清，
   不从模型参数/任意历史文本捏造目标、食物或营养，也不新增一条替代更新。
4. 回合被拦截/失败时，不额外附加容易被误解为个人结论的系统知识卡。
   成功回合仍保留知识依据；真正的安全警报和已核实保存回执不受影响。

无新外部 API/客户端类型或迁移；如调查发现必须扩大数据契约，先更新此 spec。
不回填生产记录、不更改安全阈值、不纳入不可信血氧源、不将缺失值当正常。
