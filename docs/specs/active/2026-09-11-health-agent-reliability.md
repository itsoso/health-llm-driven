# Feature Spec: 健康 Agent 证据与执行一致性

> Status: local-candidate; live-verification-blocked
> Owner: 当前 Health Harness 实现任务
> Updated: 2026-09-11
> Related PRD: `docs/prd/reva-personal-health-os-prd.md`
> Plan: `docs/plans/2026-09-11-health-agent-reliability-improvement.md`
> Dossier: `docs/dossiers/2026-09-11-health-agent-reliability.md`

## 1. Decision

在既有 Agent 流程中修复正确领域、目标日期、真实终态及医学证据约束；保持后台为事实、授权与执行真源。

## 2. Problem

线上只读评测发现：技术成功不等于任务满足；部分日期和领域错误导致误解释或误写；重复不可恢复调用增加等待。采用合成反例，不将生产原文、健康值或账户标识写入本规格或测试。

## 3. Requirement Admission

采用关联计划 §3 的 RequirementAdmission；用户于 2026-09-11 授权按计划实施。映射 HealthTwin、SafetyGuardian、WriteIntent、ExecutionEvent。产品准入通过，医学及发布验收仍由独立审阅和实际验证裁决。代码变更授权不等于 commit/push/deploy 授权。

## 4. Non-Goals

不增加处方、诊断、自动调整补剂能力；不批量修正生产历史；不恢复旧工作流，不扩大外部模型同意范围。

## 5. Product Object Mapping

| 对象 | 契约 |
|---|---|
| HealthTwin | 读取结果绑定业务日期、观测来源和可用性 |
| SafetyGuardian | 对危险叙事采取受控处理，来源目录不证明个体断言 |
| WriteIntent | 意图领域、实体、动作和授权与工具参数一致 |
| ExecutionEvent | 回执验证正确对象，失败/确认/不确定与成功分离 |

## 6. User Flow

明确事实记录 → 确认身份/数量与授权 → 正确领域写入 → 回读 → 显示可验证结果。
睡眠或饮食查询 → 解析目标时段 → owner 范围读取 → 区分有数据/缺失/不可用 → 呈现依据和受控解释。
失败 → 保留已知项 → 定向澄清或安全对账；同一不可恢复原因不循环调用。

## 7. Surface Contract

Backend 负责检查、记录与终态；Mobile 的 token、done、历史、复制/语音只能消费通过边界检查的内容。保持已有字段向后兼容，旧客户端也不得把失败显示成成功。使用 iOS 模拟器作为默认 UI 验收环境。

## 8. Data Contract

- 优先复用 turn_outcome、write_receipts、answer_evidence.v1 和现有调用 schema，不新建平行状态体系。
- 日历读取若引入 start_date/end_date，只接受服务端从已授权请求投影的有界窗口，不能信任任意模型时间范围；执行层再次验证 owner 与范围。
- 日期窗口使用闭区间业务自然日；sleep 的目标是指定醒来归属日，不能取两天内最新旧记录冒充昨晚。
- 读取空结果与查询失败必须分别表达；不能静默回退其他日期。
- 不预设 schema 迁移；若不可避免，先追加受管迁移、兼容与 PostgreSQL 验证证据。

## 9. Safety, Privacy, And Medical Boundary

补剂/用药记录只表示事实，不推断新增方案。模型不得将补剂变成饮食以满足营养校验，不得用任意资源回执宣称目标完成。医疗断言检查不能只靠末尾免责声明或通用引用；未知因果不能升格成诊断，基因风险不得驱动剂量。所有观测与写入保留用户隔离和审计，不输出原始医疗载荷、凭证或内部错误参数。

## 10. AI Behavior

模型可提取候选、解释已有证据、问缺失字段；授权、领域、日期与回执由确定性代码核对。高风险生成内容在流出前受控；允许明确的科普、否定提醒与已核实医生原始指令，不能以整轮含“医生”豁免生成内容。安全检查失败时保守输出并记录可操作原因，不伪装完成。

## 11. Acceptance Criteria

- Given 明确补剂摄入 When 用户请求记录 Then 正确领域写入且无饮食行；数量歧义先澄清。
- Given 两个自然日睡眠且目标日缺失 When 查询昨晚 Then 明确缺失，不用旧日数据替代。
- Given 合法历史饮食记录 When 查询该日 Then 返回该日 owned 数据；错误/无数据分别显示。
- Given 需要修正的已有餐食 When 明确份量调整 Then 仅更新目标行，重复确认不重复缩放。
- Given 已持久化待选项 When 当前会话有效编号回复 Then 正常继续；跨会话或过期编号不继承授权。
- Given 工具协议文本或未完成动作 When 终态输出 Then 不显示成功或原始协议；历史与即时状态一致。
- Given 无依据医学方案 When 生成回答 Then 不向任何消费面泄漏危险指令；正常科普不受误伤。

## 12. Verification Plan

各改动先 RED 再 GREEN，运行关联计划 §8 的定向测试并追加真实 PostgreSQL 语义验证。最终跑受影响测试、类型检查、LLM change gate 与所需 live gate。结构覆盖变化后重生成 System Map 并验证。证据写回同一 Dossier；缺少真实环境不得写通过。

## 13. Rollout And Rollback

先固定候选、安全独立审查与精确 revision CI。发布需用户另行授权。出现错写、越权、重复执行、危险指令或失败误报立即停止受影响能力推广；不得回退到已知不安全路径。历史数据修正需单独核验和授权。

## 14. Open Questions

真实线上性能目标与医学审阅待候选完成后核验；不阻塞可确定的错误修复。所有未覆盖硬件、第三方交接和真实发布结果保持 Unknown。

## 16. 候选实现契约与限制（2026-09-11）

- 普通和多模型生成正文统一在完整质量与医学边界检查后显示和保存。已执行查询产生的确定性卡片可先显示；不再承诺 provider 的每个增量立即发送到客户端。规则命中是阻断依据，规则未命中不证明医学安全。来源标签明确“未逐句核验”，不能冒充支持性引用。
- 个性化 AI 日报缺少受审医学依据时保留确定性数据摘要，并记录 `blocked/high_risk_missing_evidence`；不把建议草稿写入聊天或 SOAP。此边界改变个性化日报能力，重新开放需完整依据与医学验收。
- 日历读取限饮食和睡眠、有界自然日（最多 31 天），睡眠按醒来日期归属。返回 window、availability 与限制；同步状态未知时明确 unknown。现有日聚合行无法证明完整睡眠事件或重建跨时区旅行的归属。
- 内部确定性餐食份量修正使用 v2 签名绑定 owner、记录、更新载荷与服务端读取基线；锁内重读校验，旧基线返回 409，无效签名返回 403。公开通用 PUT 没有新增 CAS 契约，也没有数据库迁移。
- 服务端 pending choice 只恢复当前拥有者、当前会话、最新助手正文哈希及有效期内的闭集只读选项。有效期最多 600 秒；不把旧的无时区时间作为有效授权。编号在历史中保留原文，执行使用明确日期。写选项仍走原确认流程，受限只读回合不走多模型捷径。
- 不可恢复语义拦截使用同轮规范化请求缓存并停止重复模型轮次；可修复参数错误仍可更正。下一轮重新决策，不跨轮缓存授权。
- 终态区分完成、失败、阻断、等待确认、拒绝及待对账；医学 hold 和协议污染不得算成功。Mobile 恢复以权威 terminal status 为准，不能从非空正文推断完成。
- 客户端指标 `metric_version=2` 与旧版本分别统计。进度、正文、引用与关键卡片分开；受控 `client_turn_id` 仅接受系统格式。关键内容绘制不等于已核验答案。
- 本地 Session 评测导出按 owner 与明确关联投影匿名元数据，不读取正文，不建生产接口。输出使用调用方 HMAC 秘钥匿名化；跨源一致性由调用方只读 repeatable-read 事务保证。未定价成本、未标注任务满足率、无法归属的版本/别名都保持 unknown；无 run 的用量单列。
- 简单记录上下文已避免继承无关上一问；非快速路径的背景注入策略仍未全面修改。本轮没有同请求线上性能改善证据。
