# 新建对话开场修复

> 状态：实现中，尚未发布。2026-10-10。

## 决策与问题
“新建”开始新话题，使用即时、确定性的问候，不续接上一次行动。正常进入聊天仍可展示主动提醒。截图中的设备读数被当作行动标题，过期行动被称为今天到期，独立拉取的记忆又被误标为该开场的“医嘱依据”，三者叠加造成误导。

## 需求准入
- classification: 既有交互语义与来源归属修复。
- first_user_fit / core_loop_step: 用户自主发起记录或咨询，降低开始操作的负担。
- first_class_objects: 既有 ActionCard、会话、记忆；不新增健康对象。
- target_surface: Mobile 聊天空状态与后端主动开场。
- source_of_truth: 本地显式新建状态；正常提醒的 owner-scoped ActionCard。
- safety_level: 来源准确性与行动提醒，启用 safety overlay。
- prescription_or_causal_verdict: 无；autonomy_tier: 用户触发。
- evidence_provenance: 新建问候不声称健康依据；独立记忆不能作为其他开场的来源。
- claim_hedging: 不给出健康判断；verification_window: 本轮回归与发布后模拟器验收。
- success_metric: 新建不再出现旧复盘或旧连续性消息；真实行动不被纯指标过滤误伤。
- added_user_burden: 无；spec_required: yes。

## 实现与边界
1. 显式新建和 newChat 路由参数设置 freshStart，并用同步 ref 阻止同轮发送注入旧开场。
2. 后台异步刷新继续保存数据，但当前新话题不显示旧 opener/memory，也不显示另一套旧 starter 行。
3. 文案：“想记录饮食、体重，或聊聊今天的健康情况？直接告诉我就好。”
4. 键盘收起时展示已有“拍照记一餐”“记录体重”本地入口；键盘弹出仍有可独立理解的文字。
5. 普通进入保留既有主动提醒。开场分支去掉无关联记忆 footnote；记忆自身展示仍保留来源入口。
6. 后端在原始完整标题上完整匹配纯 Readiness/HRV/身体电量快照。条件行动及不确定标题保留，之后才做人性化截断。
7. 当天文案明确“今天可以回顾”；过期文案用“之前安排了”，不再把负天数钳制为零。

API、数据库、认证和写入契约不变。无新增模型调用、无新增提示输入 token。不会删除服务端历史或长期记忆。非目标：修改真实告警、添加每日计划能力、以本次文案修复替代其他故障修复。

## 验收与回退
- 普通打开有提醒、显式新建无旧提醒；异步返回不复活。
- 首条发送不注入旧 opener 或记忆；显式外部 context 仍保留原有流程。
- 纯设备读数不能成为待复盘行动；含阈值条件的真实行动必须保留。
- 过去/当天/未来日期文案准确；不同用户隔离维持既有测试。
- Mobile Jest、类型检查、后端回归、独立评审；上线另需固定 SHA CI/部署/OTA/模拟器证据。
- 如需回退，回退本批代码与对应发布候选；不清理健康记录。
