# 面向目标的产品规划 v2 —— 从「造大脑」转向「能用、能获客、能证明」

> 状态:战略再排序 · 2026-06
> 目标(回顾):Agent-Native 抗衰/中年健康产品 → 高价值人群 → 可演示、可获客、**可融资**(估值杠杆=真实 outcome + 低 CAC)。
> 上游:strategy-longevity-os / product-evolution-plan / plan-next-horizon。

---

## 0. 一个必须诚实面对的判断

过去几十个 PR 把**后端"大脑"造得很厚**(202 services、多专家、飞轮、群体证据、harm 信号、因果记忆、多模型 panel、成本路由…)。但盘点发现:

- 新能力 **mobile UI 消费 = 0**(next-data / cohort / causal-notes / parse-photo / eval / funnel 全无界面)
- 3 个能力 **flag 默认关**(成本路由、多模型 panel、specialist 工具化)= 线上不生效
- 用户实际能看到的抗衰功能 **只有 1 个**:首页「身体年龄卡」

**结论:大脑 >> 能被触达的产品。** 相对于"可融资 / 高价值人群愿付费"这个目标,瓶颈已经**不是再加后端智能**,而是:**把已有能力变成用户/投资人能摸到的产品 + 跑出第一个真实 outcome + 建获客入口。**

> 工程铁律提醒:继续堆没人用的后端 = 复杂度债 + 自我欺骗式进度。下一阶段**少写新后端,多接线、多surface、多验证**。

---

## 1. v2 三大支柱(按对目标的杠杆排序)

### 支柱 A · 最后一公里:把"大脑"接到用户面前(P0)
已有后端,缺 UI/接线。**复用 > 新建**。
- mobile「身体年龄」页升级:接 `next-data`(下一步补什么)+ `causal-notes`(因果记忆)+ 群体证据(matched cohort)→ 一个完整的"抗衰主页",而非孤零零一张卡
- 拍照录入(parse-photo)接 mobile:相机 → 解析 → 确认 → 入库(冷启动最大摩擦)
- admin 把 eval/funnel/harm/cohort 做成**一页看板**(给自己/投资人看"产品在起作用"的证据)
- 把 flag-off 的能力(成本路由/panel)接到真实调用点或明确下线(不留悬空 primitive)

### 支柱 B · 第一个真实 outcome(P0,估值杠杆①)
目标的硬通货是"有人真的变年轻了"。
- 端到端**引导式 onboarding → 首个 12 周 N-of-1**:注册→拍照传体检→建 Twin→PhenoAge→开 N-of-1→(12周)→对比卡。每步埋点(漏斗已就位)
- 招 1-3 个种子用户真跑(产品+运营,非纯代码)
- 产出第一张"生物年龄 −X 岁"真实对比卡 = 路演实物

### 支柱 C · 获客入口(P1,估值杠杆②低 CAC)
目标的 GTM 从未落地。
- 难言之隐/精力隐私问诊入口(product-evolution MVP 一直没建)= 高转化引流
- 直播私域内容 → 问诊 → 建档 漏斗(创始人最强项),测真实 CAC
- 这部分**重运营/内容**,工程只做承接(问诊流 + 履约 skill)

---

## 2. 明确"先停"的事(避免继续过度建设)

- ❌ 再加新后端 specialist / watcher / 聚合 primitive(除非有 UI 立即消费)
- ❌ 继续做 flag-off 的"安全 primitive"(成本路由、panel 已够,先接线或下线)
- ⏸ 复杂度债大重构(agent_executor 2817)——仍按"随手拆",不专项

---

## 3. v2 优先级

| 优先级 | 事项 | 性质 | 杠杆 |
|---|---|---|---|
| P0 | 抗衰主页(接 next-data/causal/cohort) | mobile,复用后端 | 让大脑可触达 |
| P0 | 拍照录入接 mobile | mobile + 已有 parse-photo | 冷启动 |
| P0 | 引导式 onboarding→首个 N-of-1 | mobile + 漏斗 | 第一个真实 outcome |
| P0 | admin「证据看板」一页(eval/funnel/cohort/harm) | 前端,复用端点 | 路演弹药 |
| P1 | 难言之隐问诊入口 | 产品+工程 | 获客 |
| P1 | 直播私域漏斗承接 | 运营+工程 | 低 CAC |
| P1 | flag-off 能力接线或下线 | 后端收尾 | 去悬空 |
| P2 | 临床 co-sign(信任天花板) | 业务+工程 | 高净值信任 |

---

## 4. 第一刀(v2 起步,纯代码可立刻做)

**抗衰主页 v1**:把已上线但没界面的 `next-data` + `causal-notes` 接进 mobile 首页/身体年龄页——用户第一次能看到"我该补什么数据、我的事件如何影响指标"。这是"最后一公里"里最便宜、最直接体现"大脑价值"的一步,且纯 RN/TS、OTA 可发。

---

## 附:诚实声明
本规划基于代码盘点:新能力 mobile UI 消费=0、3 flag 默认关、用户可见抗衰功能仅 1 个——所以判断"瓶颈是 surface/接线/获客,不是再加后端"。支柱 B/C 含大量非工程(种子用户、内容、运营、合规),工程只是其中一段,不应按纯工程排期。第一个真实 outcome 是估值硬通货,代码替不了。
