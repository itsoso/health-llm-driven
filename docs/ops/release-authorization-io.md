# 发布授权历史校验的 I/O 优化

本次来源：用户询问「授权校验已运行约 8 分钟，累计磁盘读取约 8 GB」所指的操作并要求优化。

## 操作与基线

这一步是 `scripts/bootstrap_trusted_release.py rotate`，在部署前为新源码 revision 轮换受限发布授权。它核验旧操作终态、授权撤销、原锁、历史 Web/OTA 回执及备份制品；不是后端部署已完成的证据。检查失败仍阻断轮换。

原始会话进程 90431 的 08:00 采样：`rchar=6680793629`、`read_bytes=8016338944`。前者是进程读取字节计数，后者是内核记录的存储层读取，包含文件系统实际 I/O，不能将二者等同于唯一数据集大小。

2026-10-10 对生产 `frontend-publications` 仅做元数据清点：四组保留构建/依赖备份合计 2,727,305,688 字节、210,290 个目录项，耗时 16.82 秒。没有读取或输出文件正文。`rotate` 在写退休 intent 前和真正退休前各调用一次 `_assert_idle`，两次均进入历史制品全文哈希校验。这部分未变化备份单独就产生两轮约 5.45 GB 内容读取；其他历史和 Git 检查也有 I/O，不能断言 8 GB 全部来自这一项。

## 优化范围

仅在一次持原始 launcher/build 锁的 `rotate` 内创建局部 `backup_memo`，只共享给这两次检查；无磁盘缓存、无 TTL、无跨命令信任。install/revoke/recover、RPC 和 live 构建内容均保持全量读取。

首轮仍核验完整字节并与原始回执中的摘要比较，摘要格式保持兼容。记录前后完整库存指纹：相对路径、对象类型、设备/inode、owner/group/mode、链接数、大小、纳秒 mtime/ctime 及链接目标。文件以 `O_NOFOLLOW` 打开，读取前后 `fstat` 身份必须不变；扫描中变化阻断，不写入 memo。

第二轮仍重读回执、遍历全部库存、验证权限和链接边界，并两次核对库存指纹。仅指纹完全一致才复用第一次验证过的内容摘要。变化会重新计算内容；新增、删除、同大小改写后恢复 mtime、inode/权限变化、逃逸链接及扫描中变化均不能取得旧摘要放行。未验证的摘要不进入 memo。

两个阶段输出脱敏的 STARTED/VERIFIED、耗时及已缓存备份数量到 stderr；stdout 的原结果/回执协议保持原样。阶段未返回 VERIFIED 不能宣称完成。

## 性能与交付边界

本地同盘合成对照：2,048 个文件、512 MiB；同一库存分别执行两轮旧算法和新算法。旧内容读取 1 GiB，新内容读取 512 MiB；摘要完全一致。暖文件系统实测 1.17 秒与 0.60 秒。此结果验证重复内容读取减半，不代表生产 8 分钟可直接折算为 4 分钟。

生产下一次执行必须从受审、CI 通过的新 canonical SHA 加载工具，并记录两阶段耗时。未上传本机脚本替换线上 bootstrap，也未重放旧发布操作。当前发布网络阻断与此优化独立；优化不会使未部署的后端或未发布的 OTA 自动变为成功。
