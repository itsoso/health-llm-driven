# PRD: Agent 多图餐食采集事务

## 目标

用户在小巴对话中一次选择或连续拍摄多张同一餐照片后，系统将其作为一个输入事务处理：只创建一条饮食记录、关联全部照片、展示一个可恢复回执，并允许后续在同一记录上修正。

## 用户故事

1. 我拍摄同一餐的正面、侧面或剩余量照片，系统只记录一餐。
2. 我切换 App、断网重试或重新打开会话，照片和回执都不丢失、不重复。
3. 识别有误时，我修改原记录，而不是生成一条新记录。
4. 某一步失败时，我看到准确阶段和可执行的重试，而不是泛化错误。

## 产品不变量

- 一个 `source_message_id/client_turn_id` 对应至多一条上下文餐食记录。
- 一个已验证 `DietRecord` 在同一会话中只投影一张回执卡。
- 卡片和历史元数据不持久化短期签名 URL。
- 所有照片读取均 owner-scoped；删除记录必须处理其全部照片资产。
- 图片识别值是估算，修正保留审计来源。

## 成功指标

- 多图 exactly-one record 成功率 100%（自动化回归）。
- 重试导致重复记录/重复卡片为 0。
- 会话重开后全部已关联照片可恢复。
- 捕获至可见回执的 P95 不高于现有单图基线的 1.5 倍。
- 无跨用户图片能力泄漏。

## 非目标

- 不做食物秤级精确营养承诺。
- 不引入新的通用工作流框架或媒体 CDN。
- 不改变处方、诊断或临床建议边界。
