# PRD: 隔离发布执行器

## 需求与决策

让本次饮食修复通过安全发布链到达测试者。复用现有健康记录写入边界及 App Store 发布 Dossier，不重新定义健康业务需求。

发布命令只携带精确提交和固定目标；源、执行脚本与工具来自 GitHub 控制面认可的提交及锁定依赖，不从本机可写工作区打包执行。

## 范围

- 新建独立、手动触发的 GitHub 托管 workflow；默认 validate，不自动部署 push/PR。
- 仅允许当前 main 的同一 workflow SHA 且精确 CI 通过；错误、缺失、取消和仍运行均阻断。
- 后端仍用 deploy.sh 的全部恢复/迁移/健康/回滚流程；禁止给发布 workflow GitHub contents write。
- TestFlight 仅创建测试包及上传，不改正式审核表单、不提交 App Review、不 OTA。
- 无生产凭据阶段先完成源与测试身份检查；凭据缺失时拒绝发布，不复制个人全权私钥作为便捷旁路。
- 模拟器只作为本机 QA，物理同包能力、系统分享交接、相机/麦克风和 Apple 审核结果不得从模拟器推断。

## 验收与非目标

错误 SHA、旧 main、非绿/新失败 CI、环境污染和缺失凭据有行为负例；真实托管 validate 有精确 run 回执。生产完成必须另有后端终态、EAS/ASC 制品身份以及模拟器实际结果。

不修复其他开放 PR、不扩大健康数据使用、不创建长期 root 级云端凭据、不移除现有事务安全闸。信任 GitHub 控制面、审核源、固定工具链和生产主机 root，不宣称抵御这些主体失陷。
