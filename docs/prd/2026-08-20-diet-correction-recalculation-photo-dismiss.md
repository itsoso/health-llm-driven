# 饮食修正重算与餐食大图滑动关闭 PRD

## 1. 目标

关闭两个已观测的饮食纠正断点：用户在聊天卡内改变食物或份量后，正式记录中的营养必须随新描述重算；用户展开餐食照片后，可用自然的纵向滑动退出大图。

## 2. 用户价值

- 不再出现“文字已改成两碗，热量仍是一碗”的内部矛盾。
- 一次保存即可完成食物和营养同步，减少手工计算负担。
- 大图查看符合移动端手势习惯，同时保留明确关闭按钮。

## 3. 产品要求

1. 只有食物描述相对已保存记录发生变化时，保存才触发营养重估。
2. 重估结果必须经过后端既有非食物过滤、数值边界和 totals 重算；客户端不得信任模型自报总量。
3. 重估与写入由一条 owner-scoped 服务端命令完成；模型调用期间不持行锁，落库前重新校验版本，食物、热量、蛋白、碳水、脂肪和纤维在一个事务中写入。
4. 重估失败或没有任何可用营养时，不修改记录，保留编辑内容并给出可重试错误。
5. 食物未变化时，用户仍可手工修正已有营养或餐次，不强制调用 AI。
6. 展开照片后，明确的纵向滑动关闭；横向滑动继续用于多图分页；关闭按钮继续存在。

## 4. 真实性边界

这里的“重新计算”仍是基于用户描述的营养估算，不是称重或实验室测量。UI 和数据 provenance 不得把它描述为医学精确值；无法估算时宁可不写，也不保留与新食物不一致的旧数字。

## 5. 验收

- 将“一碗虾滑鸡蛋汤”改为“两碗虾滑鸡蛋汤”并保存时，只发送一条原子重算命令，不再发送旧 180 kcal/旧宏量值。
- 重估失败或并发冲突时，记录零修改且编辑器保留输入。
- 保存成功后聊天卡以服务端完整回读值刷新，服务端返回空值时也必须清掉旧值。
- 纵向滑动达到阈值时大图消失；短滑动和横向滑动不关闭；叉号仍可关闭。
