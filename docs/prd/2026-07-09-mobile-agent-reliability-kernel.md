# Mobile Agent 可靠性内核 PRD

> Status: approved for implementation
> Date: 2026-07-09
> Related: `docs/specs/reva-product-governance-spec.md`、`docs/prd/reva-personal-health-os-prd.md` R1/R5/R10

## 1. 目标

让 Mobile 小巴的每轮交互从“发出消息并等待一段文本”升级为“发出一个可恢复、可验证的任务”：输入状态明确、执行过程可见、写入结果带真实回执、切后台或重开后能恢复，失败时保留用户输入并给出下一步。

北极星不是对话时长，而是：用户发出健康意图后，系统正确完成并能证明完成。

## 2. 用户问题

当前高频问题集中在同一根因：没有统一任务状态。

- 按住说话和实时听写分别占用 audio session，状态切换容易互相干扰。
- 发送后只看到流式文本，无法区分查询、写入和验证阶段。
- 卡片按钮本地显示完成，不一定包含资源 ID；重新进入历史后状态可能丢失。
- App 切后台、回前台或进程重建时，流式状态、键盘、图片和草稿分别恢复。
- Agent 回复下方固定动作过多，容易重复执行已经完成的记录。

## 3. 产品原则

1. **事实先于文案**：只有 API/tool 的结构化结果可以产生“已写入”状态。
2. **失败保留现场**：消息、草稿、附件和可重试信息不能因失败消失。
3. **一次只有一个输入状态**：文字、按住录音、实时听写、转写和提交互斥。
4. **一次只有一个主行动**：回复默认展示最相关的一个动作；其他能力按需展开。
5. **Mobile 是执行面**：模型、工具和耗时信息默认折叠，不把主界面做成调试台。

## 4. 用户故事

### US1 可恢复对话

用户发送请求后切到其他 App，再回来时能看到该轮是仍在执行、已完成还是失败；不会出现半截消息覆盖本地流。

### US2 可验证写入

用户确认饮食、行动、WriteIntent 后，卡片显示资源类型、资源 ID 或 executed_ref、完成时间。缺少可验证标识时卡片保持失败/待确认，不显示完成。

### US3 稳定语音输入

左侧切入“按住说话”，松开后发送或右滑转文字；右侧麦克风实时转文字，再点一次禁用。发送、切后台或切到另一种语音方式时，当前监听立即停止并释放麦克风。

### US4 草稿和图片不丢

用户选图、拍照或输入长文本后离开页面，再回来仍能看到未发送草稿；发送成功后历史消息使用后端持久 URL，不依赖 iOS 临时文件。

### US5 低密度结果

Agent 回复先展示结论和一个主行动。记录卡、议程卡等原子能力负责写入；不再在每条回复下固定展示“加入计划/保存记忆/生成记录/继续追问”。

## 5. 成功指标

- 确认写动作产生可验证回执的比例：100%。
- 同一 action 重复点击或重连造成重复提交：0。
- 语音提交后麦克风仍激活：0。
- 前后台切换后 turn 进入错误终态或消息消失：0（覆盖自动化场景）。
- 未发送草稿/图片在普通页面重建后恢复率：100%（App 私有文件仍存在时）。
- 通用回复动作从固定四个降为零或一个上下文动作。

## 6. 数据流

```text
用户输入（文字 / 按住说话 / 实时听写 / 图片）
  -> ComposerController（唯一输入状态 + 本地草稿）
  -> useChatEngine / AgentTurn（submitted -> running -> verifying）
  -> POST /agent/stream
  -> AgentExecutor / allowlisted tools / manual-confirm write path
  -> SSE status / tool_result.receipt / done
  -> AgentTurn terminal state + WriteReceipt
  -> Chat card / Today / Agenda cache refresh
  -> 历史消息与资源事实可恢复
```

## 7. 范围

### P0 必须完成

- AgentTurn 状态机和恢复。
- WriteReceipt 结构化合同和 fail-closed。
- Composer 状态机、audio 互斥和生命周期释放。
- 文字与图片草稿恢复。
- 已执行写动作的防重复和持久反馈。

### P1 体验收敛

- 回复动作按上下文出现，移除固定四动作。
- Today Focus 在对话开始或键盘出现后收起。
- 首 token 前使用人话阶段；失败提供重试，不丢当前内容。
- 启动数据避免相互覆盖和空态闪烁。

### P2 信任与人格

- 小巴形象保持一致，不用装饰抢占内容。
- 明确显示“本轮用了什么记忆/数据”，允许进入记忆管理。
- 记录 turn、voice、receipt 的关键事件，支持后续 p50/p95 与成功率分析。

## 8. 非目标

- 不新增诊断、处方、剂量调整或自动服药写入。
- 不发送原始语音消息，不做后台常驻监听。
- 不新增数据库表；需要时复用 `WriteIntent.executed_ref`、记录 ID、消息 meta。
- 不在本轮迁移 OSS/KMS/CDN；继续使用现有认证上传和历史 URL。
- 不重写 Chat 页面或引入新的状态管理依赖。

## 9. 验收

- 每个新增 reducer/helper 先有失败测试，再实现。
- Card action 无资源标识时测试必须保持 error，不得进入 done。
- AppState background 测试确认两条语音均停止。
- Enter 提交测试确认实时听写停止且状态回到 idle。
- 历史恢复测试确认 server image URL、cards、completion status 和 receipt 保留。
- iOS Simulator 走查文字、两条语音、图片、键盘、前后台和长回复。
