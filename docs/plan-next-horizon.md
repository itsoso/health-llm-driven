# 下一步改进点(Next Horizon)—— 从「有机器」到「机器可信且聪明」

> 状态:思考草案 · 2026-06 · 基于已上线(eval+funnel 仪表、主动化泛化、cohort 泛化、飞轮)
> 上游:`docs/plan-product-improvements.md`(P0/P1 多已落地)
> 视角:产品已建成 测量→主动→学习 三层机器。下一前沿是**质量/智能/信任**,不是再加机器。

---

## Tier 1 · 我刚引入的风险(应最先补)

### ⚠️ 主动触达全局协调(P0)
**问题**:主动化已从 longevity_watch 泛化到 trajectory_watch,**两个周任务各自有打扰预算,但没有跨 watcher 的全局预算**。同一用户一周可能同时收到「生物年龄」+「体重」+「血压」多条推送。随着主动化继续推广到 recovery/safety/更多垂直,**触达噪声会指数恶化** —— 这正是我前几刀亲手做出来的风险。
**改进**:一个**触达协调层**(global notification budget):
- 跨所有主动 Agent 的全局频次预算(如每用户每周 ≤N 条 insight)
- 同周多条 → 按严重度/价值排序,合并或择优(只推最值得的一条)
- 去重(同指标重复触发)+ 静默期沿用
- 复用已有 `notifications` + `agent_audit_log`(eval 看板已能看推送率,加"被抑制数")
**为什么 P0**:这是已存在的回归风险,且越往后推广越严重;不补,主动化越强=越扰民。

## Tier 2 · 智能深化(护城河)

### 飞轮 v2:匹配队列(matched cohort)
现在 cohort 是**人群平均**(「X% 改善、平均 Y」)。下一步按相似用户分层(年龄/性别/基线区间)→「**和你相似的人**做了 X」。让推荐从平均值变成个性化。
- 复用 `cohort_metric_outcomes`,加分层维度;严守去标识 + 最小样本(分层后样本更小,抑制阈值更要守)
- 仍是 observational,不说因果;但"相似人群"显著提升可信度与转化

### 依从性智能(adherence)
outcome 最大杠杆是**用户到底有没有执行**。现在追 outcome + decision,但不追协议**中途的依从/掉队**。
- adherence-watch:检测 N-of-1 周期内掉队(打卡/数据停更)→ 温和再激活(走触达协调层)
- 这直接抬北极星(完成闭环且改善的用户)——没完成的多半是掉队,不是无效

## Tier 3 · 信任 / 安全(规模化前提)

### LLM 合成层安全 eval(red-team)
51 条确定性规则覆盖**已知**风险,但 orchestrator 的 **LLM 合成层**仍可能过度承诺 / 说错 / 漏护栏。
- 建对抗性 eval 集(已知危险 query → 期望 agent 不越界),CI/定时跑,接 eval 看板
- 比"埋点"更进一步:主动测 agent 输出的安全性,不只观察

### 可解释 + 主动学习
`JudgmentFeedbackBar` 已收用户对判断的反馈。深化:
- 用户能问"为什么推这个"(reasoning trace 已有基础)
- 从用户纠正中学(active learning):被频繁 declined/false_positive 的建议模式 → 降权

## Tier 4 · 增长 / 广度 / 工程

- **冷启动信息增益引导**:数据稀疏时,"测哪一项/记哪一条信息增益最大" → day-1 价值
- **成本/延迟分级路由**(方向十,已设计待落):高风险→reasoning,日常→fast,flag 门控
- **复杂度债**:`agent_executor.py`(2817)、`orchestrator.py`(1795)是热点,改动频繁×体积大=风险,优先"随手拆"

## 取舍与排序

```
先(补自己挖的坑,P0):    Tier 1 触达全局协调
再(护城河,纯代码可起步):  飞轮 v2 匹配队列 → 依从性智能
然后(规模化前提):         安全 eval red-team
并行/随手:               成本路由(已设计)、信息增益引导、复杂度债
```

**一句话**:产品已经"能测、能主动、能学习";下一步是让它**不扰民(协调)、更懂你(匹配队列)、能落地(依从)、可信任(安全 eval)**。其中**触达协调是 P0**,因为它是我把主动化泛化后亲手留下的回归风险。

## Tier 5 · 更远的改进点(前 4 Tier 未覆盖)

### ⭐ 群体 harm 信号(反向飞轮 / pharmacovigilance)
飞轮现在只 surface「改善了多少」。它应**同时** flag「哪些干预在群体里和 worsening 相关」——
cohort 已经在数 worsened,几乎免费就能出"反向证据"。
- 把飞轮从"只报喜"变成**两面诚实的证据** = 最强可信度 + 安全/伦理强项
- 例:某补剂队列 worsened 率显著高 → 安全预警,而非继续推荐
- 纯代码、用现有 cohort 数据;严守 observational(相关非因果,样本量)

### 数据质量 → Agent 置信度门控
Twin 多源、新鲜度参差(已有 freshness 分区),但 Agent 可能对**陈旧/稀疏数据过度自信**。
应让数据质量分**反向调节措辞**:数据差 → 多 hedge、少断言、先建议补数据。信任 + 安全底层。

### 主动 Agent 跨垂直语义冲突防护
3 个 watcher 的全局预算解决了**频次**叠加,但没解决**语义矛盾**(恢复说"休息" vs 运动说"加量"
同周触达)。cross_review/arbitration 已用于同步 orchestrator,应延伸到主动触达。

### 多模态录入降摩擦(拍照 → 化验解析)
冷启动最大摩擦是手动录入。化验报告**拍照 → OCR → 进 Twin**(已有 text import,缺 photo→parse)。
day-1 价值与漏斗 activated 率的最大杠杆。

### 临床 co-sign / human-in-the-loop
持牌医生/营养师**复核并联署** Agent 建议(已有 doctor-weekly-report 雏形)。抬信任天花板 +
打开 concierge / B2B2C 变现。

### A/B 实验框架
漏斗能**度量**转化,但**提升**需实验框架(对照 copy/干预/触达时机)。没框架 = 拍脑袋优化。

**取舍**:最该先做 **群体 harm 信号**(纯代码、近免费、两面诚实);其次 数据质量置信度门控
(影响全产品信任底层)。其余按业务节奏。
