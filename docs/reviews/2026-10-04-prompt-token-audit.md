## Prompt 的主要体积来自哪里

25 条可用分项日志的字符预算累计：工具定义 60%，系统内容 31.29%，history/tool-result 4.15%，当前 user 内容及注入 4.54%；整数截断使分项总和略有偏差。

轻量工具决策轮的 system 已降至 163 个估算单位，却仍发送 11 或 17 个工具，工具本身占 4,160 或 6,741 个估算单位。有的请求正文仅 2–7 个单位，仍背负 4,160 个单位的工具定义。进一步缩短轻量 system 的收益很有限。

源码证据：

1. `agent_executor.py::_tool_names_for_turn` 已定义领域/快速工具集合，但 `backend/app` 中只有定义，没有运行调用；邻近单测仍在直接测这个 helper。
2. 实际 Pi 入口从 `get_health_tools()` 开始，再应用材料、goal、只读范围等授权过滤。授权过滤保留了大量与任务无关的合法工具。
3. `_resolve_chat_provider` 使用 `pass_tools = tools`；快模型选择改变模型，未替当前轮收窄 schema。
4. `domain_prompt_optimization=true` 已在环境配置启用。因此不能通过“打开现有开关”宣称恢复了工具子集优化。

生产代码上只做 schema 序列化的只读测量：全部 schema 为 6,741 个字符预算单位；已有 fast 子集 3,437，analysis 2,873，recovery 2,349，knowledge 207；仅 environment_check 为 141。这是可重现的候选体积差异，**不是上线 token 节省或质量验收**。

25 条带 usage 的最终回答中，15 条 `completion_status=error`，累计输入 389,394，占这些回答输入的 61.86%；其余 10 条完成回答输入 240,114。该比例是**带 usage 的保存回答样本**，不是全部线上请求失败率。部分 error 是正确拒写或歧义澄清，不能取消安全检查换取“成功”。窗口内已有份量修正、饮水补录等后续修复，因此应先在当前版本复现再决定修改。

这些记录里的模型调用大多 `success=true`，但用户任务仍失败。只盯 provider 成功率、每次 token 或平均响应长度，会掩盖昂贵但未完成的任务。

今天最新的天气例子已用现行纯函数复现：`classify_answer_task_tier("今天天气怎么样？", has_attachments=False)` 返回 `high_stakes`；语义为 `advice / unknown / advice_frame`，触发未知建议的保守地板。**不需要历史污染也能重现风险升级。** 高风险地板随后绕过领域精简，完整上下文又给回复提供了无关健康背景。应补明确的公共天气意图，不得把未知医疗问题整体降档。

## Laya 应该承担什么

同窗口 32 条带决策元数据的回答：接受 1、低置信度弃权 24、超时 7；超时均约 5 秒。报告到的 Laya 输入合计 2,339，超时输入为未取得用量，不能视为真实零消耗。它目前不是输入成本主因，但超时会增加用户等待。

上一轮本地 Laya 优化尚未发布；不能把本窗口当成改后效果。现有枚举也不能细分公共天气等所有任务，仅改置信度规则不足以解决当前问题。

建议让 Laya 为**固定任务类型与工具集合**提供有界候选，供服务端任务编译器校验。可信度低、复合意图或未知输入走现有保守路径；执行工具仍取已授权集合的交集，绝不靠 Laya 授予写权限或降低临床地板。对确定可解析的天气、帮助介绍和已验证回执，规则路径可以直接完成路由，无须额外问 Laya。部署环境先量测延迟再收紧截止时间并做熔断；不要拿本机几十毫秒的结果直接设生产阈值。

## 按收益与风险排序的实现批次

| 顺序 | 修改 | 验收重点 |
|---|---|---|
| 0 | 修 caller 作用域；请求绑定 run/call/phase，补齐早返回路径 usage | vision 后恢复外层 caller；取消、异常、并发用户不串上下文；日志仅存长度/计数 |
| 1 | 在真实 Pi 模型请求边界接回固定任务工具集合，并与已有授权过滤取交集 | 测 provider 实收 payload；覆盖复合任务、缺工具恢复、附件、否定写入和跨用户拒绝；不能只测 helper |
| 2 | 公共天气、助手介绍独立任务；只注入必要地点/时间，不预载病史和全量工具 | 天气仍实际取数；地点不明精确澄清；天气+症状/用药保持医疗保护；尊重用户显式模型选择 |
| 3 | 先编译有边界的读写任务，失败时停止无意义重试；验证回执后直接展示结果 | 澄清提前；查询结果可以确定性出表；写入权限、幂等、回执核验原样保留；医学分析仍保留证据轮 |
| 4 | 按任务拆系统内容，保留稳定公共前缀；本轮才附短动态证据 | 不删除安全规则；保留来源、日期、缺失和风险状态；优化缓存不能重新塞回无关信息 |
| 5 | 将 Laya 候选用于上述任务集合选择，按部署环境设置超时预算 | 单独验证覆盖率、错误候选率、超时率与端到端收益；不把部分能力置信度当完整 tier 信任 |

第一批目标设为：在当前版本同一组去标识任务回放中，简单公共信息/明确单领域请求的每个已完成任务输入下降至少 30%，P95 不恶化，任务完成率不下降，新增越权写入/临床安全回归为零。30% 是候选验收目标，不是本次已取得效果；不满足则回退对应任务通道。困难医学问题不强设低 token 上限。

比较同时记录每个任务的 input、cached/unknown、output、真实模型调用数、工具重试、首个有用结果时间、端到端 P50/P95/P99及终态。允许的安全澄清单列，不能通过少回答、隐藏失败或移除保护来达标。现有 25 条预算日志不足以给出全站节省预测，也不足以验证图像尺寸优化。
