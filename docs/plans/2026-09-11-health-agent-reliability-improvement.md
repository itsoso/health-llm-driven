## 1. 目标与范围

让健康 Agent 先取得正确时间、正确对象的数据，再给出符合证据和医学边界的回答；用户要求记录或修改时，验证实际结果，失败时提供最小可恢复步骤。

本轮优先做稳三个流程：

1. 睡眠查询 → 确认目标夜晚和数据完整性 → 解释 → 安全的今日建议。
2. 餐食记录 → 图片确认 → 保存 → 份量修正 → 历史饮食复盘。
3. 补剂/用药事实录入 → 身份、数量及授权核对 → 正确领域保存 → 回执。

不在本轮扩大诊断、处方、补剂方案自动调整、主动干预或通用旅行/媒体能力；不替换模型或重建 Agent 架构。模型选择只作为后续同请求对照实验，不能代替本轮语义修复。

最小可交付切片：一条明确的补剂记录，经过意图识别、领域校验、现有授权路径、数据库写入及回读，最终在 Mobile 展示正确终态；有歧义则只问缺失字段，不产生饮食记录。

## 6. 工作包与验收

### T0 — 冻结可复现问题与行为契约（P0；后端 + 测试；所有包的入口）

- 从问题模式重建合成案例：补剂误入饮食、同名实体、歧义数量、跨午夜、未同步、昨天饮食、上一餐修正、短选项、协议污染、有回执但对象错误、无依据因果、泛引用配具体方案。
- 不复制真实对话、患者特征组合、数值、图片、数据库 ID 或 run_id。用新的日期、实体和合成数值，使案例不能还原原账户。
- 基于 feature-spec-template 固化下述契约及端到端场景，指定每个工作包负责人。记录基线模型/版本/参数和各分母。
- 新行为先形成真实失败测试；环境错误不算 RED。若主干已有修复且测试通过，则记录复验证据，不为完成清单重复实现。
- 验收：每类错误有最小反例及不应阻断的正例；预期含授权、数据效果、终态和答案依据；不只断言字符串或 mock 被调用。

### T1 — 约束高风险健康叙事（P0；后端 + 医学/药学审阅）

- 审计普通、快速、工具失败、跨轮、流式、历史回放和复制/语音等回答出口；高风险正文在进入用户可见流之前受控，不只在 done 之后补引用。
- 区分已核实医嘱转述、一般科普、个人建议、未知因果。基因风险不能直接生成个体剂量或“必须吃”的指令；未核实资料不得变成增减清单。
- 来源绑定到实际支持的断言及适用条件；只有目录或无命中时明确限制。数据缺失不推成异常，设备评分不直接推成诊断或激素机制。
- 失败时返回可解释的核验/就医讨论项和安全的非药物建议；记录脱敏原因，不静默改写、不伪称已核验。
- 验收：所有安全反例阻断；普通科普、否定句、已核实医嘱转述正例保留；不能靠结尾免责声明通过。医学审阅待完成前，不开启受影响的高风险输出。

### T2 — 写入领域与回执一致性（P0；后端）

- 将用户明确的对象领域、实体、数量、动作绑定到执行意图；模型参数必须与其一致。补剂不能为满足营养 schema 改成饮食。
- 复用现有补剂身份解析和记录路径；名称或数量歧义仅澄清冲突字段。图片或历史上下文不能自行成为新补剂身份授权。
- 在写入前验证领域，在写入后验证资源类型、拥有者及关键参数；多动作保留逐项状态，不能用任意一条回执覆盖所有动作。
- 验收：合成补剂记录产生正确领域事件且不产生 diet_records；同名、多数量、否定、跨用户、重复提交正反例通过 PostgreSQL。未授权不写，不确定已写入时先对账。
- 历史误写的修正属于另一个数据操作任务；本轮先生成受限、只读候选核验，不自动删除或迁移生产记录。

### T3 — 真实终态和正文完整性（P0；后端 + 移动端）

- 复用 turn_outcome 的现有状态，审计各 executor 路径是否传齐未执行、阻断、回执与待确认信息。
- `complete` 不能仅由非空文本或任意回执决定。记录需证明目标动作完成；查询需区分成功读取、无数据、无法访问和等待同步。
- 工具协议片段不得作为持久化/流式用户答案；检测到片段时给出明确失败状态，不能把清空后的正文重新标成功。
- 保持 done、运行查询、历史、卡片、复制和语音消费的一致性；旧客户端无法理解新增字段时也不能误显示成功。
- 验收：未写入/写错对象/协议污染反例不显示成功；图片待确认不显示失败；部分写入/断连后回读不重复执行；正常 Markdown 保持可用。

### T4 — 时间窗口与设备同步语义（P0；后端）

- 明确目标日期、时区、睡眠起止与归属规则；跨午夜查询只能取得候选集，最终必须选择与目标夜晚匹配的事件。
- 记录业务日期和采集/同步时刻的区别。返回数据日期、更新状态、可用性及限制；缺失目标记录不把最近旧记录当成目标。
- “同步设备”交给真实支持的同步能力；只有状态查询能力时诚实说明，不能调用 health_record 冒充同步。同步运行中与数据分析分开判定。
- 验收：昨晚/昨天/明确星期与日期、午夜、时区切换、设备延迟、部分数据、重复/跨源记录均有 PostgreSQL 证据；回答、卡片、证据标签使用同一时间选择结果。

### T5 — 历史查询与原记录修正（P1；后端 + 移动端；依赖 T2/T4）

- 为受控读取表达明确日期范围、领域和 owner；补齐旧接口不能表达的日期能力，不直接删除安全规则。
- 上一餐使用服务端拥有者范围、时间和记录标识定位；多个候选时展示最小选择，不让模型猜记录 ID。
- “吃了部分份量”在确认后更新对应记录并回读；幂等重试不重复缩放，不用新增另一条掩盖修改失败。
- 验收：已有历史可读，空数据与访问失败区分；修改仅影响目标行，汇总同步；重复确认、并发编辑、断连恢复、跨用户全部通过；无法定位时保留原记录。

### T6 — 有限重试和定向澄清（P1；后端 + 移动端；依赖 T3）

- 同一轮中，相同规范化请求和不可恢复 reason_code 不重复调用；只有事实、授权或参数发生有效变化才允许重新决策。
- 对临时网络错误复用受限重试；写入状态未知时转对账，不盲目再次写。
- 短输入先匹配当前会话服务端 pending choice；过期、跨会话、不匹配的编号不继承旧意图。
- 明确一个实体只有数量冲突时，只问数量；不输出 calories、参数名或跨领域通用示例。
- 验收：重复语义拦截次数为零；当前有效编号能继续、失效编号不能执行；正常多步不同工具调用不被误阻断。

### T7 — 简短回执与分层回答（P1；移动端 + 后端；依赖 T1/T3/T4）

- 简单记录先显示已核实回执；数据查询先显示目标时间和关键事实；复杂解释按需展开。没有证据时先说明缺口。
- 只带入影响当前决策的健康背景；闲聊和位置更新不反复附带旧病史、药物清单或个体化阈值。
- 复用现有快路径、证据编译器和面板。逐段内容在呈现前遵守 T1，不能为了 TTFT 提前流出未经检查的高风险方案。
- 性能优化按同一请求阶段证据决定；不预先引入跨轮缓存。若确需缓存，必须定义 owner/key/数据版本/TTL/失效，并验证同步后不会读旧结果。
- 验收：合成固定集与适用任务分组对照；安全、准确性不退化，简单任务减少等待与无关输出。不能用进度动画代替有效答案。

### T8 — 任务级评测、埋点与成本（P1；后端 + 测试 + 移动端；T0 后即可启动）

- 用受控关联 ID 接通输入、运行、工具动作、独立卡片确认、回执、重试及客户端绘制；同一逻辑任务只算一次，尝试次数另计。
- 明确定义 progress、正文绘制、已核验关键事实、可执行卡片和任务终态。废弃 first_interactive 被当作有效答案时延的报表口径；保留旧埋点版本兼容。
- 将明确失败、合理待确认、主动取消、真实无数据、拒绝及未知分开。长期健康收益不混入任务执行正确率。
- 关联前台与后台用量，保留 API usage/估算/缺失标识；补价格来源和套餐口径。不把缺失成本当零，不把后台成本算作某个聊天任务成本。
- 验收：可重算分母、状态、采样缺失和成本覆盖；无原文/敏感字段泄漏；双用户隔离测试；报表能够暴露“技术成功但语义错误”。

### T9 — 后台预算及授权失败恢复（P1；后端）

- 分开处理预算超限、预算守卫不可用、模型故障和用户尚未同意服务提供方；保留真实失败原因。
- 审计日报是否有可用的非生成内容及用户可见状态；不能从模型调用失败次数推断日报失败份数，也不能凭预算充足就关闭守卫。
- 验收：授权不足不调用未获准服务；预算守卫异常时明确停止受影响调用；恢复有节流、无重复发送，费用和交付结果分别可查。

### T10 — 候选验证、发布及效果观察（发布另行授权）

- 精确绑定候选 SHA，完成项目要求的 CI-mode 集成闸、真实主干 CI、安全审阅和相关文档/生成物验证。局部测试不得替代。
- 默认 iOS 模拟器验收；不主动要求真机。相机实拍、硬件及第三方 App 交接未覆盖项逐项标注，遵循 simulator-review-acceptance，不能把未验证记为通过。
- 后端与 Mobile 按兼容性顺序发布；OTA 与原生发布边界分别判断。遵守当时受审部署入口、权限和发布冻结状态。
- 观察至少 7 天；没有足够真实样本则延长，报告数量与分布。只读观测不自动修正患者记录，不向其他账户重放真实对话。

## 7. 验收指标与停止条件

下列为目标，不是已测得的提升。固定回归集先验收正确性；真实性、隐私和医学安全不允许用更快速度交换。

| 指标 | 定义 | 首阶段目标 |
|---|---|---|
| 关键错误 | 错领域写入、无依据高风险指令、协议答案、失败误报成功、越权 | 已知反例及扩展对抗集 0 例；线上发现 1 例即停止受影响能力推广 |
| 日期/实体准确 | 输出证据与请求目标、实际行一致 | 确定性案例全部正确；不能从引用存在推断正确 |
| 合法任务误阻断 | 有效授权且数据/字段齐全却被策略拒绝 | 正例回归不得新增；真实比例上线后分任务统计 |
| 可执行任务满足率 | 授权及信息齐全的任务，结果经读写/答案核验满足意图 | 固定合成验收集 ≥95%；关键安全错误仍单独零容忍；真实基线先标注，不预填 |
| 重复不可恢复调用 | 同任务同请求同原因无新信息再次调用 | 0 |
| 定向澄清总耗时 | 收到输入至有效澄清问题可见 | P95≤3 秒 |
| 简单读取/记录 | 同类任务从输入至已核验结果可见；人工确认耗时单列 | P95≤15 秒 |
| 复杂分析首个有效事实 | 排除占位进度、泛引用及未核验医学建议 | P95≤20 秒；完整结果 P95≤60 秒作为第二步目标 |
| 追踪及成本 | 逻辑任务关联覆盖；用量来源；计价缺失率 | 已采集任务可解释，缺失显式显示；完整成本覆盖前不承诺降本幅度 |

真实性判定依赖任务类型：记录看正确资源回读，查询看目标数据，修改看原行差异，建议看支持性与医学审阅。用户“确认记录”只证明执行意愿，不能代替记录正确性。

性能对照采用同一合成语料、数据快照、模型配置和环境，保留逐请求阶段、P50/P95及样本量；改变模型或缓存必须单独标记。每个性能分组目标至少 100 次自动回放，不能把低样本 P95 当稳定结论；真实线上数量不足时仅报告区间与个案。

停止/回退：出现越权、错写、重复写、危险指令外泄、终态误报，立即停止受影响路由推广并按受审回退方案处理；未授权不得远程改配置。性能相同口径 P95 连续两个窗口恶化超过 20%，或正例准确性下降，停止扩量并调查。窗口建议为每组累计 100 个有效任务；不足时延长，不机械按小时判定。

回退不能重新开启已知不安全输出。若旧版本不满足安全边界，暂停受影响能力并保留读取/核验路径。写入后的错误数据单独审计、授权修正；代码回退不代表数据已修复。
