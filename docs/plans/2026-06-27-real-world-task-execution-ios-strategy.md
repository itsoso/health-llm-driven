## 1. iOS 平台能力硬事实（决定一切，先看这张表）

| 能力 | iOS 原生 | 说明 |
|---|---|---|
| **发起一通电话** | ✅ 交接式 | `tel:` URL（RN `Linking.openURL('tel:…')`）。弹"呼叫 X?"，**用户点、用户说**；app 不能静默拨号 |
| **进到通话里说话 / 听通话音** | ❌ **绝无可能** | 蜂窝通话音频完全沙盒，**无任何公开 API** 注入 TTS 或读取通话音频。CallKit 只服务 app 自己的 VoIP，碰不到蜂窝线 |
| **自动导航 IVR（按 1 按 2）** | ❌（蜂窝线） | 同上，无音频通道 |
| **驱动其它 app 的 UI 去操作（挂号 app / 微信）** | ❌ | iOS 沙盒，没有安卓那种 Accessibility 自动化。唯一正路：**App Intents / 快捷指令**（仅对暴露 intent 的 app）+ URL scheme + 分享面板 |
| 拟短信（用户发） | ✅ 交接式 | `MFMessageComposeViewController`；预填内容，用户点发送 |
| 写日历 / 提醒 | ✅（授权后） | EventKit |
| 串联自身能力给 Siri/快捷指令 | ✅ | App Intents；仓库已有 Siri + `modules/shared-keychain` 基建 |

**核心结论：iOS 注定当不了"通用操作手机的 agent"。** 连 Google Duplex 那种"AI 打电话帮你订"也**不跑在手机上**——它跑在服务器电信栈里，手机只负责触发。"让 Reva 自己拨号并对坐席讲话"在 iOS（及任何原生手机）上不可行，这是平台限制，不是 Reva 能力问题。

## 2. 分层模型（刚需怎么落）

把"替我办事"拆成三层，价值/风险/可行性递进：

### L0 — 本机交接（= concierge 文档的 Phase 0；现在就能上，零外呼风险，拿下 ~80% 价值）
Reva 干完所有**脑力活**：判断该联系谁、查到对的号/入口、拟好"要问什么/要说什么"、把用户资料备齐 → **一键 `tel:` 拨出 / 一键拟短信 / 一键写日历** → 用户说 30 秒 → app 录音转写（需单独同意）→ 用户审自己的转写 → 批准后**下游全自动**（落议程 + 出发提醒 + 检查事件 + OCR 结果回流 + 立基线 + 到点复查再触发）。
> 洞察：这个刚需的痛点 **80% 是摩擦与断点，不是"AI 必须开口"**。L0 把整条闭环跑通，只少一个"拨号机器人"。

### L1 — 线上办事 skill（**优先于电话**；服务端，复用 P5 范式）
中国大量"预约/办事"已**线上化**：微信挂号小程序 / 京东健康 / 支付宝医保 / 医院公众号 / 各类办事入口。对这些，正解是**服务端 OpenClaw skill**：用**用户自己的账号**跑线上流程，**逐笔确认 + 审计 + 网关熔断**（与 P5 快手电商 skill、`food_order` 同范式）。比电话机器人**更可靠、可追溯、更合规**。
> 这是覆盖"做其他事情"刚需的**主力**，比纠结 iOS 电话 API 价值大得多。

### L2 — 服务端自治外呼（**永久先冻 501**，最后一公里）
= 服务端克隆声音对真人坐席讲话。撞**两堵墙**（见 concierge 文档 §0/§10）：① 中国无个人外呼 PSTN 通道（主叫须企业实名 + 话术报备；400 只进不出）；② 克隆声音对真人讲话强制 AI 披露 +《标识办法》+ 声纹 PIPL 单独同意。**三关全过前不解冻**。

## 3. 决策规则：线上优先，电话兜底

```
要办一件事
  ├─ 有线上渠道(小程序/web/app)？ → L1 服务端 skill(用户账号 + 逐笔确认)   ← 默认
  └─ 只接电话？                    → L0 一键 tel: 拨号 + 脚本 + 录音审 + 闭环  ← 兜底
真·AI 开口对坐席讲话(L2)          → 冻 501，三关全过前不碰
```

## 4. 复用盘点（现成度，避免重造）

| 能力 | 现成位置 | L0/L1 怎么用 |
|---|---|---|
| 一键拨号 / 拟短信 | RN `Linking` / `MFMessageComposeViewController` | L0 交接出口 |

| 网关熔断范式（501） | `food_order_skill_gateway.py` / `kuaishou_skill_gateway.py` | L1 新 skill + L2 `place_call` 抄它 |
| "用用户账号办事 + 逐笔确认 + 审计" | P5 `ReorderIntent` 全套 | L1 线上办事 skill 直接克隆架子 |
| 预约意图识别 | `doctor_booking` 意图 | L0/L1 入口 |
| 结果回流 | OCR 化验回流管道 | 闭环尾段，**不新建管道** |
| 端上触发 | Siri + App Intents + `modules/shared-keychain` | L0 一键动作 / 快捷指令 |
| 一等对象 + 同意 | concierge 文档已定 `ConciergeIntent` + `consent_grants` + 录音清除 cron | L0 落库先于任何电信集成 |

## 5. 一等对象与同意（治理）

- **L0 电话闭环** → `ConciergeIntent`（concierge 文档已定，克隆 `reorder_intent.py`）+ `consent_grants`（声纹/录音 PIPL **单独同意**，独立于 onboarding ToS，一键撤销删声纹模型）+ 录音短 TTL 清除 cron。
- **L1 线上办事** → 复用 P5 `manual_confirm + audit` 范式；可新增通用 `TaskIntent`（或按域分：挂号/缴费），逐笔强确认，绝不代输支付/身份凭据。
- 安全门：propose + 执行两处走 `evaluate_rules_with_status`（`failed_rule_count==0` + consent 有效），fail-closed。

## 6. 分期（仅排序，本文不实现任何一项）

| 阶段 | 风险 | 内容 |
|---|---|---|
| **L0（先上）** | 低 | concierge 闭环 minus 拨号机器人：`ConciergeIntent` + `consent_grants` + 录音清除 cron + 一键拨/脚本 + 转写审 + 下游全自动。零外呼/身份/克隆声音风险。**= 用户要的"操作手机去预约"的可上线合规版** |
| **L1** | 中 | 通用"线上办事 skill"范式（先挑一个目标渠道，如微信挂号），用户账号 + 逐笔确认 + 审计 + 网关熔断 |
| **L2（最后）** | 高 | 监督式克隆声音外呼；三关全过（企业开线+话术过审 / 招商信诺确认允许授权 AI / 身份财务级合规+council 评审）前 `place_call` 永冻 501 |

## 7. 硬边界 / 风险（继承 concierge 文档 §10）

- 对外、难撤销、带身份、含生物特征（声纹）、录第三方音 —— **Reva 迄今风险最高的写操作**。
- 财务 / 身份 / 声纹相关一律走**独立同意屏 + 安全评审**，不抢跑合规。
- 不上自治外呼，直到三关全过；线上不自由发挥；身份/保单/支付绝不中途读、必须执行前逐项确认。
- iOS"本机通话桥接"现实性需打折：蜂窝线注入不了音，所谓"桥接"实为**通话时屏幕引导** 或 **VoIP/SIP 旁路**（Reva 能控的线，非蜂窝线），不是真把 AI 塞进蜂窝通话。

## 8. 开放问题（启动实现前必答）

3. L0 录音/声纹同意屏的法务措辞（PIPL 单独同意 + 撤销路径）。
