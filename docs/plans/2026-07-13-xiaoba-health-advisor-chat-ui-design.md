# 小巴健康参谋型对话界面设计

## 1. 目标

把 Mobile 小巴从“聊天气泡和功能卡片的堆叠”收敛为“健康参谋型混合对话”：用户先看清结论，再看关键数据，只面对一个下一步行动，需要时才展开依据、性能和分享能力。

这不是把小巴改成通用聊天工具，也不是把对话页改成健康仪表盘。Chat 保留上下文连续性，结构化动态卡片负责执行、确认、修正和回执。

## 2. 已确认方案

采用“健康参谋型混合对话”，而不是纯消息流或卡片 Feed。

固定回答层级：

1. **小巴结论**：一到两句话直接回答问题。
2. **关键指标**：只显示真正改变判断的指标。
3. **一个可执行行动**：一个主按钮、一个次按钮。
4. **折叠依据**：数据来源、模型透视、性能、分享和朗读按需展开。

原型：

- Figma：<https://www.figma.com/design/wzEQSjlzz8hPjJ5VqyspwY?node-id=1-2>
- 三个关键状态：回答完成、思考中、拍照记餐。

## 3. 信息架构

### 3.1 顶部

- 高度保持紧凑，只显示小巴、模型入口、新建、历史、更多。
- 模型名是次级信息，不与小巴标题竞争。
- 顶部不再显示“回复中”。运行状态只属于当前 assistant turn。
- 图标视觉尺寸保持轻量，触控区通过 `hitSlop` 满足可用性，不用大圆底扩张高度。

### 3.2 消息区

- 用户消息继续使用右侧绿色气泡。
- 普通 assistant 回答取消大面积白色圆角外壳，直接落在 paper 背景上，用留白、标题和分隔建立层级。
- 只有真正的结构化对象使用卡片：行动、记录草稿、图表、安全提示、确认和回执。
- 长文本优先分成“结论 / 指标 / 行动 / 依据”，不把 Markdown 原样堆成报告。

### 3.3 动态卡片

统一语法：

- 顶部：对象类型、状态和必要的置信/安全标签。
- 中部：结论或结构化数据。
- 底部：一个主动作 + 一个次动作。
- 主动作必须是当前最可能执行的行为，如“加入今天”“确认记录”“开始执行”。
- 次动作只用于“调整”“查看依据”“稍后”，不同时出现多个同级按钮。
- 成功后原卡转为回执或可撤销状态，避免再次要求确认。

### 3.4 证据与透视

- 数据来源、思考步骤、模型、轮次、Token、耗时和工具详情统一归入一个“依据与过程”入口，不再出现“使用数据”和“透视”两个孤立胶囊。
- 完成态不在正文上方保留“思考完成”胶囊；思考步骤在“依据与过程”内可回溯。
- 微信和小红书是用户高频分享目标，以低对比度轻量入口常驻同一工具栏；复制、选择和朗读仍通过长按出现。
- 医疗边界与高风险提示仍直接可见，不因渐进披露被隐藏。

### 3.5 输入区

- **本轮不改。** 保持现有微信式文字/语音切换、长按说话、加号入口和输入框尺寸。
- 只允许上方内容区为键盘和输入区正确让位，不调整语音交互或视觉。

## 4. 状态设计

### 4.1 思考中

页面只能存在一个运行状态源：当前 assistant turn 内的 `ThinkingStepsPanel`。

- 一个活动指示器，不同时出现两组转圈。
- 能确定步骤时显示 `当前步骤 / 总步骤` 和线性进度。
- 当前步骤用动词描述，例如“读取最近睡眠”“核对用药记录”“整理下一步”。
- 已完成步骤保留简短回执，未开始步骤弱化。
- 正文区域预留稳定骨架，避免完成时整体跳动。
- 保留停止能力；错误必须显式变成可重试状态，不能用无限思考掩盖。

### 4.2 回答完成

- 思考面板退出正文流，完整步骤收进“依据与过程”。
- 结论先出现，结构化行动随后出现。
- 证据和执行过程位于回答末尾并使用一个入口，默认折叠。

### 4.3 拍照记餐

- 照片作为用户消息保留在对话中，可回溯和分享。
- 识别期间使用同一个思考状态，不跳出对话制造第二个 loading。
- 识别完成后生成可编辑饮食草稿卡，主动作“保存记录”，次动作“调整”。
- 保存后显示含 `diet_record_id` 的回执，并支持短时撤销。

## 5. 长按交互

对齐微信与 iOS 的熟悉顺序：

1. 复制
2. 选择
3. 分享
4. 朗读（仅 assistant 文本）

默认动作是复制，不再把“选中消息”作为长按后的唯一结果。动作使用上下文菜单或轻量浮层，不永久占用消息底部空间。

## 6. 视觉系统

- 继续使用 Reva 现有 warm clinical token：paper、墨色和低饱和健康绿。
- 不使用渐变、发光、彩色大面积背景或深阴影。
- 页面区块不套卡片；卡片只服务于独立结构化对象。
- 统一 4pt 间距体系；正文行高强调可读性，标签和透视信息明显降级。
- 圆角控制在现有 token 范围内，避免所有内容都成为胶囊。
- 动态内容使用稳定最小高度和骨架，避免流式输出时跳动。

## 7. 不做什么

- 不改语音输入框和微信式长按说话。
- 不恢复底部四 Tab。
- 不新增通用聊天“模式选择”占据首屏。
- 不允许模型自由生成任意布局；继续使用白名单动态 UI schema。
- 不修改健康结论、药物建议、安全规则、数据查询和写入自治级别。
- 不用隐藏失败、来源或医疗边界换取视觉简洁。

## 8. 验收标准

- 流式回复时顶部不出现第二个“回复中”状态。
- 思考区最多一个活动指示器，并显示可理解的当前步骤。
- 普通 assistant 长回答不再被大白色圆角卡包裹。
- assistant 消息下方只保留一条轻量工具栏：“依据与过程 / 微信 / 小红书”，不再常驻四个大胶囊按钮。
- 长按消息首先提供复制，并可继续选择、分享和朗读。
- 普通完成回复具备“小巴结论”层；有结构化指标和建议时使用指标网格与单行动卡。
- 结构化行动卡最多显示一个主动作和一个次动作。
- 拍照记餐照片仍在消息流中；未确认草稿按“识别摘要 / 食材 / 营养 / 修正”呈现，保存后有回执。
- `ChatInputBar` 的文字、语音、长按和尺寸视觉无变化。
- iOS 小屏与常规屏无内容遮挡、重叠或因流式状态引起的明显布局跳动。
