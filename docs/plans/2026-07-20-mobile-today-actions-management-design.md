# Mobile 今日行动管理链路设计

## 背景

小巴对话中的“管理今日行动”当前跳转到隐藏 Tab `/alerts`。该页面聚合全部活跃行动卡与安全告警，既不是今日议程，也不在可返回的原生 Stack 中。结果是用户无法自然回到小巴，并在一个混合历史提醒、洞察和内部规则标签的列表里找不到可执行操作。

## 目标

把日常执行链路收敛为：

```text
小巴动态卡片
  -> 今日行动（只显示今天需要处理的事项）
  -> 完成 / 稍后 / 跳过 / 调整 / 问小巴
  -> 服务端确认写入
  -> 今日列表与小巴卡片同步刷新
  -> 返回小巴
```

## 方案选择

采用独立 Stack 页面 `/agenda`，不继续复用隐藏 Tab `/alerts`。

- 相比修补 `/alerts`：保持“安全告警”和“今日执行”职责分离，不再混合历史行动卡。
- 相比半屏 Sheet：长列表、原因选择和调整操作拥有足够空间，系统返回手势也更可靠。
- 复用现有 `/agenda/today`、`/agenda/complete` 和 React Query 缓存，不新增数据模型或自动写入路径。

## 信息架构

### 顶部

- 左侧：返回按钮；有导航栈时 `back()`，深链冷启动时回到 `/​(tabs)/chat`。
- 标题：`今日行动`。
- 状态摘要：`待处理 N · 已完成 N`。
- 不展示“回放”“时间线”等分析入口，避免偏离执行任务。

### 列表

按用户意图分组，而不是按后台生产者分组：

1. `现在做`：待完成且当前可执行，按优先级和时间窗排序。
2. `稍后`：今日仍需处理，但不在当前时间窗或被用户暂缓。
3. `已处理`：今日已完成或已跳过，默认折叠，可回看结果。

高风险安全告警不进入普通行动列表；它保留在今日页的安全入口和安全告警页中。

### 单项操作

- 主操作：`完成`。药物、补剂等保留明确的手工确认语义。
- 次操作菜单：`稍后提醒`、`跳过`、`调整`、`问小巴`。
- `跳过`需要原因，继续走 `/agenda/complete` 的 `status=skipped` 写回。
- `稍后提醒`一期只改变客户端当前会话排序，不伪造完成记录；后续接提醒服务时再增加持久化契约。
- `调整`回到小巴并携带结构化上下文，由 Agent 讨论修改，不直接静默改协议。

## 状态与错误

- 写操作期间只锁定当前行，不锁住整个列表。
- 服务端确认后再进入完成态，并同时失效 `agenda`、`timeline`、`daily-artifact` 和动态视图缓存。
- 写入失败保持原状态，显示可重试错误，不做乐观成功声明。
- 返回小巴时触发一次轻量刷新，确保对话卡片不保留旧计数。

## 视觉方向

采用“小巴的安静健康工作台”而不是卡片墙：暖白背景、低阴影、单层列表、绿色只用于当前行动和成功状态，琥珀仅用于到期提醒。内部字段如 `safety_guardian`、`anomaly_detector`、`[spo2_avg]` 不面向用户展示。

## 验收

- 从小巴点击“管理今日行动”进入 `/agenda`，不再进入 `/alerts`。
- 页面存在可见返回入口，并支持 iOS 返回手势；深链进入也能回小巴。
- 只显示今日议程对象，不混入全量历史行动卡和安全告警。
- 可完成、跳过、稍后和调整；失败不改变状态。
- 操作完成后列表和小巴卡片同步刷新。
- Voice 输入条和小巴单入口壳层保持不变。
