# 对话今日行动与验证周期渐进式改造

## 1. 决策

“加入今天计划”表示把**一条当前行动**放进今天，不等于请求系统生成七天方案。

产品层级固定为:

```text
一条建议
  -> 用户点击“加入今天”
  -> 可编辑确认
  -> 今日行动已接受
  -> 执行 / 完成 / 调整
  -> 到验证窗口后复盘
  -> 需要时才查看未来周期
```

`HealthAgendaItem` 是当前执行对象；`InterventionCycle` 是后续验证容器。客户端不得因为验证窗口是 7 天，就把未来每天都作为已确定待办展开。

## 2. 意图分流

| 用户表达 | 系统行为 |
|---|---|
| 点击“加入今天” / “把这条加入今天” | 打开确认页，不生成 `runtime_agenda` |
| “我现在下一步做什么” / “今天怎么安排” | 只展示今天第一行动 |
| “接下来 7 天怎么安排” / “本周计划” | 展示周期摘要，后续日期默认折叠 |

匹配顺序必须是“写入意图 > 明确周期 > 当前行动”，避免通用“计划”关键词再次吞掉具体语义。

## 3. Mobile 交互

### 3.1 加入今天

- 主按钮改为“加入今天”。
- 点击后直接打开现有 `InterventionDraftSheet`，不发送第二条 Prompt。
- 默认只突出:
  - 今天做什么，可编辑；
  - 一项执行检查；
  - 验证提示，默认按建议动力学推断，恢复/睡眠类优先次日回看。
- 用户点击“确认加入今天”后才写入；成功提示“已加入今天”，并刷新 Today、Agenda、Daily Artifact 和 ActionCard。
- 确认后的行动在 Today 与 Chat 使用同一执行描述，可直接“完成这一步”；完成事件同步回写来源 ActionCard，且要求再次人工确认。

### 3.2 运行时卡

- 当前行动模式标题:“今天先做”。
- 明确周期模式标题:“本周验证节奏”，不再把“7 天”作为第一视觉焦点。
- 首屏只显示行动、时机、为什么现在、验证摘要。
- 后续 6 天使用一行折叠入口:“后续按每天状态动态调整”；展开后才显示日期。
- 日行不再显示“3 项待安排”，改为“当天根据状态确认”，避免把未承诺事项伪装成计划。
- 通用动作栏紧跟摘要，因此主动作无需滚动一整屏才能触达。
- Today 与 Chat 复用同一个运行时行动构建器，避免一端可完成、另一端只能查看。

## 4. 写入合同

现有 `POST /action-cards` 增加 `accepted: boolean = false`。

- 默认 `false`，历史调用行为不变。
- `InterventionDraftSheet` 的显式确认提交传 `true`。
- 后端在同一事务中设置 `user_decision=accepted`、`decided_at=now`。
- 不接受客户端传任意 decision；仅允许布尔 accepted，降低滥用面。
- 写入失败明确报错，不做静默成功；重复点击由保存中状态阻止。
- 相同来源、标题和用户的 accepted 行动采用幂等创建，网络重试不会制造重复待办。
- accepted 写入先经过 AdviceGuard；停药、换药、加减量等医疗级行动不能因用户点击确认而绕过安全审查。
- 药物语境必须复用共享药名词库识别完整药名及位置，以药名前后动作窗口和子句规则覆盖换药、停药与中英文剂量变化；否定只覆盖协调的警示动作，跨句咨询和开放文本“医生确认”不构成可信授权；脱离药物语境时不得误伤运动或生活习惯。
- 服务端用 `accepted_create_key` 唯一索引兜住多设备并发，应用层查询只负责快速回放，不能替代数据库约束。
- `verification_days` 只生成 `check_back_date`，不再误写为行动过期时间；只有显式到期字段才能设置 `expires_at`。

## 5. 安全与边界

- 药物剂量、诊断、处方建议不因加入计划获得更高自治。
- 卡片仍显示健康管理边界。
- 没有可完成来源时，不显示一个永远不可点的“完成”；改为进入今日计划调整。
- 未来节奏是预测性编排，文案必须说明会随睡眠、记录和安全信号调整。
- 运行时写操作仅允许既有的 `daily_plan_action.complete` 合同，校验 action id、端点与 `manual_confirm`，不开放任意 URL 写入。
- Chat 与 Today 对所有 `requires_manual_confirm` 动作统一弹出可见确认；即使服务端未给定制文案，也使用安全兜底文案。
- 完成事件按用户、日期、行动和事件类型生成服务端幂等键，并由数据库唯一约束兜住并发；首次写入后响应丢失，重试仍返回已验证回执。
- 运行时意图采用正向健康语境判断；无健康信号时只接受“下一步”“今天怎么安排”等精确短承接句，不以食物名、工作名黑名单决定是否生成卡片。

## 6. 验收

1. 点击“加入今天”不会再出现 `7天验证节奏`。
2. 用户确认后，创建的 ActionCard 同时为 accepted，能进入今日执行来源。
3. 普通下一步查询不默认展开未来日期。
4. 明确七天/本周查询仍可查看周期，但后续日期默认折叠。
5. 首屏可看到“完成这一步”或“调整今日计划”。
6. 写入、错误、取消和重复点击都有确定状态。
7. 后端相关 pytest、Mobile Jest、TypeScript、doc drift、Dossier consistency 全部通过。
8. 相同建议重复确认不会产生重复行动；复盘日到达前行动不会因“验证天数”提前过期。
9. “放入今日计划”不触发周期卡；烹饪、会议、工作等明确非健康表达不误触发健康运行时。
