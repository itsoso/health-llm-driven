# 设置页定位与入口全链路审计设计

日期：2026-08-11

## 背景与问题

用户在 iOS 设置页看到“GPS 自动”，但右侧位置显示为省份“浙江”，无法确认所在城市是否已自动更新；同时需要逐项验证设置页正式环境可见入口，修复死链接、错误导航和明显 UI 问题。

只读排查确认：

- 根级 `useGPSAutoRefresh` 会在登录后的启动和回到前台时尝试刷新 GPS，并在成功后失效 profile、天气和环境相关缓存。
- 设置页展示逻辑却优先读取 `detected_location.region`。当后端返回 `city=杭州, region=浙江` 时，界面错误显示“浙江”。现有测试也把这个错误表现写成了预期。
- 设置页目标路由文件均存在，但现有测试只覆盖少量入口，无法证明每个正式环境入口都能正确导航。

## 目标

1. 设置页展示真实城市：手动模式显示手动城市；自动模式优先显示 GPS 检测城市，仅在城市缺失时回退到地区。
2. 设置页重新获得焦点后主动刷新 profile，避免定位页保存或后台 GPS 刷新成功后继续展示旧缓存。
3. 自动定位失败、权限未开或正在刷新时给出可理解状态，不把功能错误伪装成“GPS 自动”。
4. 正式环境中每个设置入口都有可执行导航测试，并在 iOS 模拟器逐项点击、返回和观察页面状态。
5. 修复审计中发现的高置信 UI 问题，但不重构设置页信息架构、不改变健康数据语义。

## 方案

### 定位数据与状态

- 提取纯函数负责选择设置页位置标签，优先级为：已启用的手动城市 → 自动检测城市 → 自动检测地区 → profile 兼容字段 → “未设置”。
- 设置页获得焦点时失效并重新获取 profile；GPS 自动刷新成功后继续复用统一的 `queryKeys.profile`。
- 定位行展示城市和模式。城市未取得时，模式文案区分“需要定位权限”“正在更新”或“尚未定位”；不把未知状态标成成功。
- 保留 `/location` 作为权限申请、手动城市和显式重新定位的唯一编辑入口，设置首页不重复实现权限流程。

### 设置页入口验证

- 建立正式环境可见入口的声明式测试矩阵，对每一行执行点击并断言目标路由。
- 对非导航动作分别验证：Apple Health、Face ID、检查更新、删除账号、退出登录。
- 增加路由存在性检查，防止文案存在但目标文件被移动或删除。
- 模拟器中使用登录态逐项执行“进入 → 首屏渲染 → 返回”，记录白屏、崩溃、持续加载、错误文案和布局异常。

### UI 规则

- 设置行保持最小 48pt 点击区域，图标、标题、右侧状态和箭头对齐。
- 右侧状态允许合理收缩，标题优先可读；过长状态单行截断。
- 每组最后一行不显示底部分隔线。
- GPS 行继续作为强调入口，但减少固定宽度造成的城市截断，并为加载/错误状态使用语义色而非一律绿色。

## 错误处理

- GPS 权限未授予：不在后台主动弹权限；设置行明确提示，点击进入位置设置处理。
- 定位或网络失败：保留最近一次成功城市，同时显示刷新失败状态；不得清空有效城市。
- profile 刷新失败：继续展示缓存数据，并提供可重试入口；错误必须可观察，不能静默伪装为最新。
- 单个设置目标页面失败不得影响设置首页；回归记录具体目标和失败表现。

## 测试与验收

- 单元测试先失败后修复：`杭州/浙江` 必须显示“杭州”；city 缺失才显示“浙江”；手动城市优先。
- 焦点刷新测试：设置页重新聚焦会刷新 profile。
- 导航矩阵覆盖全部正式环境可见路由。
- GPS hook 测试覆盖权限、节流、跨城漂移、反向地理编码和缓存失效。
- TypeScript、ESLint、相关 Jest 套件通过。
- iOS 模拟器逐项点击正式环境入口，无死链接、白屏或不可返回页面；关键 UI 在小屏宽度下无明显截断或溢出。

## 发布边界

本次为 Mobile JS/TS/UI 修复，不变更原生依赖、权限声明、runtime 或后端契约。验证通过后可对 runtime `1.3.3` 发布 production OTA；若排查发现原生权限配置或后端接口需要变化，则停止 OTA 路径，重新评估原生构建或后端部署。
