# App Store 前全局系统加固计划

## 目标

在下周最终 RC 前，降低真实健康数据链路的越权、误写、失联通知、锁屏泄漏、网络恢复和费用失控风险。范围覆盖功能可靠性、可用性、监控、隐私安全、成本控制和发布闸门；本轮不提交 App Store。

## 优先级

### P0-A：健康数据访问边界

- 基础健康数据创建、按用户读取和 latest 读取统一使用当前登录身份。
- 普通用户只能访问自己的数据；管理员保留运维读取能力；客户端提交的 `user_id` 不能扩大权限。
- 保持现有响应结构并补未登录、跨用户和伪造 user id 回归测试。

### P0-B：生产配置与 LLM 成本

- 生产默认关闭 DEBUG 和隐式 LLM 自动恢复。
- 开启恢复时必须显式配置备用模型；预算耗尽不得自动切换到额外付费模型。
- TokenPlan 月额度必须在生产 readiness 中显式配置，并在调用前按已记账 token 加请求估算 fail-closed。
- 额度闸门是并发调用的预检，TokenPlan 控制台仍是账单真值。

### P0-C：统一通知与锁屏隐私

- open-loop 统一经过 `PushService` 的开关、静默、去重、预算、渠道和日志出口。
- 锁屏 title/body 只显示类别级文案；详细健康数据只放受保护 data，由 App 解锁后回取。
- 静默、失败、无渠道和实际送达必须能在 history/notification log 中区分。

### P1：删除验证、可观测性与恢复

- 增加 secret-free release readiness，区分 backend release 与 App Store readiness。
- 账号删除完成前增加数据库、私有上传目录和 Redis 用户范围验证报告；生产全量删除演练仍由发布周操作员执行。
- 保留网络切换、前后台恢复、图片多图、语音和真机验证为下周 G6，不以模拟器替代。

### P0-D：密钥卫生与备份安全

- 删除仓库当前文件中的历史数据库密码和测试登录密码，避免归档文档继续成为凭据泄漏面。
- 备份/迁移脚本必须从 `.env` 或进程环境读取 `DATABASE_URL`/`POSTGRES_URL`；未配置时 fail-loud，不内置默认生产凭据。
- 发布前轮换曾经出现在 Git 历史中的生产凭据；历史重写需要单独审批，不能在本轮无确认执行。

## Gate

1. G1/G2：本计划与 Health OS 数据读取、写入回执、主动通知和隐私边界一致。
2. G3：目标测试、后端集成测试、system-map drift、dossier consistency 和 release pack 全部有真实退出码。
3. G4：认证、写路径、通知隐私、删除验证和成本边界复核通过。
4. G5：只有真实生产配置满足 readiness 后才允许后端部署。
5. G6：下周最终 RC 在真实 iPhone 验证语音、相机多图、通知静默/点击回执、网络切换、前后台恢复、分享和账号删除入口。

## 明确不做

- 不提交 App Store Connect。
- 不使用模拟器或截图伪造真机证据。
- 不在没有生产数据/备份策略批准时执行破坏性全库删除。
