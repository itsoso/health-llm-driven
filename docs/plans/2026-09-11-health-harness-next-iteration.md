# Health Harness 下一轮改进计划

状态：建议计划；用户已授权提交和部署本轮健康 Agent 修复，下一轮 Harness 行为改动尚未实施。
依据：2026-09-11 源码审查、143 项现有治理测试及独立最小反例；不把计划当成已交付。

## 首先完成本轮发布

先恢复服务器到 canonical GitHub 的稳定 Git 连接（本轮实际发布在只读 readiness 被阻断），再固定候选提交，复核已通过的工程安全证据，完成合法模型同意、可用预算守卫与隔离测试数据库的真实模型验收；再核对精确主干 CI，经受审后端发布入口部署，最后发布兼容的 Mobile JS 更新并验证用户路径。不得设置虚假通过变量、关闭守卫或用旧版本 CI 代替候选 CI。

## 优先级与最小交付

| 顺序 | 改进 | 最小交付与验收 | 依赖 |
|---|---|---|---|
| 1 / P1 | 可信验收凭证 | eval artifact 绑定提交/源码、模型配置、数据集、suite、结果和时间；CI 拒绝缺失、失败、过期或错版本报告，人工授权与测试结果独立 | 沿用现有 CI 与 gate，不新建平行发布系统 |
| 2 / P1 | 验收环境预检 | 在付费调用前检查隔离合成用户、数据库角色、模型同意及预算守卫；校验依赖与锁文件一致，复用 CI 的测试分片与状态隔离，独立分片失败后继续收集其余结果但总闸保持失败；environment_blocked 与质量失败分开 | 不替用户或生产账户生成同意，不关闭安全保护 |
| 3 / P1 | 真实 Agent 闭环 | 把补剂事实、目标日睡眠、份量修正、编号继续、协议污染接入真实 Agent→工具→PG→回执路径；区分案例库存、脚本化回放、真实模型结果 | 复用本轮合成 PostgreSQL 测试与 owner 隔离 |
| 4 / P1 | 风险到测试映射 | guidance、capability policy、后台建议出口与新拆模块单独变化也触发正确 suite；不把所有文件都强制送同一昂贵 suite | 第一项报告明确 suite 身份 |
| 5 / P2 | 可恢复执行账本 | 每次尝试独立 ID，按事件顺序计算任务状态；复跑不继承旧 passed，孤立裁决失败；Dossier 由同一状态摘要派生 | 保持一个主控制器，不增加第二套完成状态 |
| 6 / P2 | 预算完整性 | 非负值、锁内读/查/写、fsync；并发不得重复序号或超限；用量来源缺失显式 unknown | 复用已有 benchmark 的锁与证据设计 |
| 7 / P2 | 路由与授权清理 | 移除不可用旧包推荐，保留 RED/GREEN 纪律；工程 GO 不自动授权 commit/push/release；支持不可变工作树快照复审 | 尊重当前可用 Skill 与用户停用政策 |

## 产品侧并行收尾

- T7：收敛非快速请求的无关背景；以同一请求与数据快照比较有效内容时延，不能用进度动画或未检查正文优化表面速度。
- T8：绑定真实部署版本和客户端版本，补有证据的 turn 别名映射与人工任务质量标注；未定价费用不填零。
- T1：补逐句医学依据与专业审阅；工程规则检查通过不等于医学安全。缺少依据的个性化日报继续保持确定性摘要。

## 执行与停止条件

先为上述已证实缺口保留能失败的最小反例，再改最小实现；独立复审与候选验证绑定同一版本。每批完成一个真实闭环再扩展测试，测试结果只在源码/依赖/数据集摘要未变时复用。出现越权、错写、危险方案外泄、失败误报或证据关联错误即停止受影响路径推广。

暂不承诺提速或成功率提升数字。部署后用同版本、同任务类型、相同统计口径观察至少 7 天；样本不足明确不足。长期健康收益另需医学和产品评估。
