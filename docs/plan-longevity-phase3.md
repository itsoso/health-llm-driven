# 抗衰方向 Phase 3 规划:从「可演示闭环」到「可规模化 / 可商业化 / 可退出」

> 状态:规划草案 · 2026-06
> 上游:`docs/strategy-longevity-os.md` §10/§13、`docs/plan-longevity-phase2.md`
> 承接:MVP(#47-51)+ Phase 2(#52-55)已全栈上线——生物年龄闭环 + 主动多维可观测。
> **诚实定位**:Phase 3 重心**从工程转向商业/运营**。只有 P3-3(群体证据)、P3-4(规模化工程)是代码先行;
> P3-1(concierge)、P3-2(商业化)、P3-5(退出)依赖运营 / 供应链 / 合规 / 资本,不能按纯工程排期。

## 0. 现状基线(已上线,核实)

- 个体闭环:体检→PhenoAge→主动 N-of-1→「年轻 X 岁」对比卡(生产可用)
- 多维信号:PhenoAge / VO2max / DNAm 三路,evidence 分级
- 主动 Agent(每周)+ eval 埋点(agent_audit_log)
- **缺口(决定 Phase 3 形态)**:① 无订阅/支付/会员基础设施 ② 无跨用户(cohort)聚合 ③ eval 仅埋点未成看板 ④ 无检测/补剂供应链对接

## 1. Phase 3 目标

| 从 | 到 |
|---|---|
| 单用户可演示闭环 | 群体可证明的生物年龄改善证据 |
| 功能 | 商业化(检测盒 + 抗衰订阅 + concierge) |
| 埋点 | eval 看板(主动推送/闭环准确率)+ 成本/延迟可控 |

北极星演进:个体「完成 ≥1 个 12 周闭环且改善的用户数」→ **群体「可证明的生物年龄改善证据 + 高净值会员 LTV 曲线」**。

## 2. 工作流

> ✅ 已有 / 🔧 改造 / 🆕 新建 · 标是否纯代码

### P3-3 · N-of-1 → N-of-many 群体证据(P0,**代码先行**)⭐
把个体闭环聚合成群体证据:「哪类干预对哪类人降生物年龄最多」——反哺产品排序 + 成为估值/并购的数据资产。
- 🆕 跨用户聚合(personal_outcome + agent_audit_log)→ 去标识 cohort outcome(按 metric=phenotypic_age/vo2max 分组)
- 🆕 admin 看板:干预类型 × 人群 × 生物年龄 delta 分布
- **严守去标识 + 隐私**(高净值数据,Tier 最高);先纯代码起步,价值随用户量增长
- 为什么 P0:纯代码、是退出叙事的硬资产、给 concierge/产品提供「什么真有效」的依据

### P3-4 · 规模化工程(P0,纯代码,RFC 方向九/十)
- 🔧 eval 看板:把 W6 的 longevity_watch 埋点 + 闭环评分做成可视(复用 `admin_slo`/`agent_audit` 既有通道)——主动推送命中率/接受率/闭环准确率
- 🔧 成本/延迟:多模型路由(已有 model_registry),抗衰分析走性价比模型;LongevitySpecialist 编排四件套的耗时优化
- 为什么 P0:扩规模前必须能度量 + 控成本,否则用户多了既不可观测也烧钱

### P3-1 · Concierge 精品层(P1,**非纯代码**,对标 Fountain Life 轻量版)
把抗衰 OS 产品化成高净值会员服务(人 + AI 混合),最高 LTV。
- ✅ 复用:LongevitySpecialist / N-of-1 / 对比卡 / personal_outcome / 主动 Agent
- 🆕 会员体系 + 服务编排(SLA、人工抗衰顾问介入点)
- **依赖**:抗衰顾问(人)、服务标准化、医疗合规边界(不诊断不开方,持牌合作)
- 中国做 Fountain Life($19,500/年)的精简版,价格不敏感人群

### P3-2 · 商业化引擎(P1,**重运营/供应链**)
- 🆕 检测盒履约(生物年龄/血检盒)+ 抗衰订阅体系 + 补剂复购
- 🆕 支付/订阅基础设施(当前**完全没有**,需从零)
- 履约走创始人直播/私域/电商(低 CAC),复用一方服务端 Agent 下单链路
- **依赖**:供应链(检测/补剂)、支付合规、直播运营——工程只是其中一段

### P3-5 · 退出叙事工程化(P2,叙事 + 数据)
- 去标识群体 outcome(P3-3 产出)+ 留存/LTV 曲线(P3-1/2 产出)→ 打包成「数据 + 预防医疗入口」资产
- 对接巨头并购逻辑(Zoetis 收 Basepaws、Mars 收 Wisdom Panel 类比:买数据 + 预防医疗入口)
- 非纯代码:随 P3-1/2/3 数据自然积累,适时成文

## 3. 排序与依赖

```
先(纯代码,不依赖运营):
  P3-3 群体证据骨架 ‖ P3-4 规模化工程(eval看板 + 成本/延迟)
然后(依赖运营/供应链/合规):
  P3-1 Concierge 精品层 → P3-2 商业化引擎
随数据积累自然产出:
  P3-5 退出叙事
```
原则同 Phase 2:**纯代码、是资产、不依赖外部的优先**。商业化/concierge 的瓶颈是运营与合规,不是代码,不能按工程速度排期。

---

## 4. 风险与边界

| 风险 | 缓解 |
|---|---|
| 高净值数据隐私 | cohort 聚合强制去标识 + 隐私 Tier 最高 + 最小化 |
| 群体证据被夸大成"疗效" | 标注样本量/置信;evidence 分级照旧;不宣称治疗 |
| Concierge 医疗合规 | 不诊断不开方;持牌抗衰医生合作;保留"请线下就医"出口 |
| 检测/补剂供应链 | 贴牌/集成不自建;补剂守《广告法》功效边界 |
| 规模化烧钱 | P3-4 成本/延迟先行;直播低 CAC |
| 伪科学红线 | 全程不可妥协(本方向生死线) |

---

## 5. 第一刀(Phase 3 最小可落地批次)

**P3-3 群体证据聚合的纯代码骨架**(去标识 cohort outcome + admin 看板):
1. 跨用户聚合 personal_outcome/agent_audit:按 metric(phenotypic_age/vo2max)+ 干预类型分组,算生物年龄 delta 分布
2. 强制去标识(不落个体可识别信息)
3. admin 只读看板 + 单测

理由:纯代码、不依赖运营/供应链、产出的是**退出叙事与产品决策的硬数据资产**,且为 P3-1 concierge「什么干预对什么人有效」提供依据。同时 P3-4 eval 看板可并行(复用 admin_slo/agent_audit)。

## 附:诚实声明
本规划基于 2026-06 对已上线 MVP + Phase 2 与代码资产的实际核实(确认**无**订阅/支付/会员基础设施、**无**跨用户聚合接口、eval 仅埋点)。P3-1/P3-2/P3-5 含**重运营/供应链/合规依赖**,不应按纯工程排期;只有 P3-3/P3-4 是代码先行。群体证据严格去标识;伪科学红线为本方向生死线。落地前医疗合规与支付合规需专业法务确认。
