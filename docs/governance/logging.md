# 日志治理

## 目标

日志用于定位业务状态、性能退化和失败原因，不是数据副本。默认生产级别为 INFO；DEBUG 只在受控调试窗口开启。

## 必须遵守

- 关键操作记录 action、稳定标识、结果、耗时和可操作错误；不得只写“失败了”。
- 禁止记录密码、Token、Cookie、密钥、完整健康载荷、完整请求体或可直接识别个人的信息。
- 用户、手机号、邮箱和外部凭证只记录脱敏或不可逆标识；优先复用 `backend/app/utils/redact.py` 与既有日志工具。
- 异常必须向调用方传播或转为明确失败状态；禁止记录 ERROR 后返回成功。
- 堆栈只进入受控 DEBUG/错误采集面；用户响应不得暴露内部路径、SQL、密钥或依赖细节。
- 敏感操作、权限变化、数据导出和管理员动作走审计日志，不以普通业务日志替代。

## 验证

新增日志时至少检查：正向路径可定位、失败路径有上下文、秘密与健康数据不泄露、动态字段不会制造高基数或告警风暴。
