# 多源数据整合 - 技术参考

## 1. 数据对齐策略

### 1.1 时间粒度问题

不同数据源的采集频率差异极大：

| 数据源 | 原始粒度 | 日数据量 | 典型延迟 |
|--------|---------|---------|---------|
| Garmin 心率 | 15秒-5分钟 | ~300-500点 | 实时 |
| Garmin 日汇总 | 天 | 1条 | 当日 |
| 饮食记录 | 餐次 | 1-5条 | 用户延迟 |
| 体重秤 | 天 | 0-1条 | 当日 |
| 血压 | 不定期 | 0-3条 | 当日 |
| 体检报告 | 月/年 | 0-1条 | 数天-数周 |
| 基因检测 | 一次性 | 一次性 | N/A |

### 1.2 对齐方法

**天级对齐（主策略）：**
所有数据统一对齐到「天」粒度：
- Garmin：取日汇总数据（record_date）
- 饮食：按 record_date 分组，汇总日总摄入
- 体重：取当日记录（如有多条取最新）
- 血压：取当日记录
- 体检：取最近一次记录值（不随日期变化，视为常量）
- 基因：永久有效，视为常量

**前一日关联（用于跨日分析）：**
分析"A → B"类关联时（如"昨日饮食 → 今日HRV"），使用 offset=1 的滞后对齐：
```
diet[day-1].protein → garmin[day].hrv
garmin[day].sleep_score → garmin[day+1].steps
```

### 1.3 缺失值处理

| 策略 | 适用场景 | 说明 |
|------|---------|------|
| 跳过 | 默认策略 | 缺失日直接跳过，不参与计算 |
| 前值填充 | 体重/BMI | 体重变化缓慢，可用最近值（7天内） |
| 不填充 | 体检/血糖 | 不做假设，标注缺失 |
| 永久值 | 基因数据 | 一次录入永久有效 |

## 2. 关联分析方法

### 2.1 Pearson 相关系数（简化版）

用于两个连续变量的线性关联：
```
r = Σ((xi - x̄)(yi - ȳ)) / √(Σ(xi - x̄)² × Σ(yi - ȳ)²)
```

**强度判定：**
| |r| 范围 | 强度标签 |
|----------|---------|
| 0-0.3 | 弱 |
| 0.3-0.6 | 中等 |
| 0.6-0.8 | 较强 |
| 0.8-1.0 | 强 |

### 2.2 分析的关联对

系统预设以下关联对进行检测：

| 关联对 | 数据源A | 数据源B | 假设方向 | 文献支持 |
|--------|---------|---------|---------|---------|
| 蛋白质摄入 → HRV | diet.protein | garmin.hrv (次日) | 正相关 | 弱 |
| 睡眠分数 → 次日步数 | garmin.sleep_score | garmin.steps (次日) | 正相关 | 中等 |
| 睡眠分数 → 次日压力 | garmin.sleep_score | garmin.stress_level (次日) | 负相关 | 中等 |
| 运动量 → 睡眠质量 | garmin.active_minutes | garmin.sleep_score (同日) | 正相关 | 中等 |
| 卡路里摄入 → 体重变化 | diet.calories | weight.weight (周均) | 正相关 | 强 |
| 静息心率 → 压力水平 | garmin.resting_hr | garmin.stress_level | 正相关 | 中等 |

### 2.3 最小样本量

- 关联分析需至少 **14天** 有效配对数据
- 低于 14 天：不输出关联结果，提示"数据不足"
- 14-30天：输出结果但标注"样本量小，结论初步"
- 30天以上：正常输出

### 2.4 证据等级标注

所有关联发现统一标注为 **D级（个人观察）**：
- 基于个人数据的统计关联
- 样本量极小（N=14-90天）
- 不代表因果关系
- 可能受混杂因素影响

## 3. 数据完整性指标

### 3.1 覆盖率计算

**单源覆盖率（30天窗口）：**
```
coverage_30d = 有记录天数 / 30
```

**总体完整性评分：**
```
overall = Σ(source_weight × source_coverage) / Σ(source_weight)
```

各源权重：
| 数据源 | 权重 | 理由 |
|--------|------|------|
| Garmin | 0.30 | 核心日常数据 |
| 饮食 | 0.25 | 营养分析基础 |
| 体重 | 0.15 | 体成分监测 |
| 体检 | 0.20 | 临床指标 |
| 基因 | 0.10 | 一次性数据 |

### 3.2 数据新鲜度

| 标签 | 规则 |
|------|------|
| 今天 | 当日有记录 |
| X天前 | 1-30天 |
| X周前 | 31-90天 |
| X月前 | 91-365天 |
| 超过1年 | >365天 |
| 一次性数据 | 基因等永久有效数据 |

### 3.3 数据状态分类

| 状态 | 定义 |
|------|------|
| 活跃 | 近7天有新数据 |
| 部分活跃 | 近30天有数据但不连续 |
| 低频 | 近90天有数据但很少 |
| 已录入 | 有历史数据（基因等一次性） |
| 未接入 | 无任何记录 |

## 4. 综合健康画像生成

### 4.1 画像结构

综合画像分为四层：
1. **用户基本信息** — 姓名、年龄、性别、数据源列表
2. **最新指标快照** — 每个数据源的最新关键指标
3. **健康叙述** — 自然语言总结（由服务端生成模板文本）
4. **数据新鲜度** — 各源最后更新时间

### 4.2 叙述生成规则

健康叙述由模板拼接生成（非 LLM），格式：
```
{age}岁{gender}，BMI{category}({bmi})，
心率变异性{hrv_level}({hrv}ms)，
睡眠质量{sleep_level}({sleep_score}分)。
{lab_summary}。
{genetic_summary}。
```

各 level 定义：
- BMI category: 使用 WHO 亚太标准
- HRV level: <50 偏低, 50-100 中等, >100 良好
- Sleep level: <60 差, 60-80 良好, >80 优秀
